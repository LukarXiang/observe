# 财务数据导入与使用

本文对应本仓库的外部财务归档和查询接口。两份资料在 `repo/` 中，导入后生成三个归档表；研究读取冻结标准表，不直接读取 Excel 或原始 CSV。

## 输入和用途

| 资料 | 导入文件 | 标准表 | 用途 |
| --- | --- | --- | --- |
| A 股上市公司财务数据 | `repo/A股上市公司财务数据（1990-2026.3.31）/年度最终合并.csv` | `financial_annual` | 年度报表及来源指标归档 |
| 同一份财务资料 | 同目录 `季度合并.csv` | `financial_quarterly` | 季度累计流量、资产负债存量归档 |
| 2000–2025 常用控制变量 | `repo/0105 2000_2025常用控制变量/常用控制变量2000_2025.dta` | `company_controls_annual` | 公司年度特征、控制变量归档 |

使用 CSV 和 DTA 可避免重复导入同一份资料的 Excel 副本。财务 CSV 保留全部原始列和原值，核心金额另建数值别名；控制变量保留 Stata 类型及变量标签。财务目录中的配套 DTA 用于核对字段标签，`原始数据/` 中的 TXT、XLSX 用于核对含义和单位，应保留。

本机三个文件与远程交接记录的 SHA256 一致。年度 95,486 行 / 949 列，季度 405,867 行 / 835 列，控制变量 73,738 行 / 127 列。每次实际导入的统计和限制以 `data/audits/financials/<import_id>.json` 为准。

## 导入

从仓库根目录执行，先选对应平台已记录的环境。Windows 用 `D:\envs\quant\.venv\Scripts\python.exe`，WSL 用 `~/envs/quant/.venv/bin/observe`（Python 3.12.12），Mac 用项目 `.venv` 中的 Python 3.12.14 和 `uv run --frozen`。依赖版本参考根 `pyproject.toml` / `uv.lock`，已有环境版本一致时无需重装；不要在 Windows/WSL 仓库目录运行裸 `uv sync` 或复用 Mac `.venv`。

以下为本机 WSL 命令：

```bash
~/envs/quant/.venv/bin/observe --root data data import-financials \
  --annual 'repo/A股上市公司财务数据（1990-2026.3.31）/年度最终合并.csv' \
  --quarterly 'repo/A股上市公司财务数据（1990-2026.3.31）/季度合并.csv' \
  --controls 'repo/0105 2000_2025常用控制变量/常用控制变量2000_2025.dta' \
  --definitions 'repo/A股上市公司财务数据（1990-2026.3.31）/原始数据' \
  --work-dir "$HOME/.cache/observe-financial-work"
~/envs/quant/.venv/bin/observe --root data data status
~/envs/quant/.venv/bin/observe --root data data snapshot --note '财务归档后冻结'
```

导入需要已发布的证券主数据和交易日历。流程持有数据写锁，先分块转换、审计，再原子发布财务表、字段字典和可用性记录。未知证券、重复报告期及异常数值仍有来源行号和隔离记录，不能把“归档成功”当作“严格历史可用”。失败时不推进发布指针。

输入、说明、映射版本和主数据相同时，重跑返回 `unchanged` 并校验归档文件。主数据或字段证据变化时会生成新归档；旧分区、旧快照和实验仍保留。源文件内容变化是新来源，需要重新审查。

`--work-dir` 可省略，默认中间文件在 `data/staging/financials/`。WSL 下 Windows 挂载盘的小文件写入较慢，上述参数把分块文件放到 Linux 盘，最终标准分区、审计和隔离记录仍写到 `data/`。它不改变导入身份或字段口径。Windows 用 PowerShell 的 `& 'D:\envs\quant\.venv\Scripts\observe.exe'` 执行同一组参数，省略 Linux 工作目录；Mac 用 `uv run --frozen observe`，同样省略该参数。

## 字段与时间口径

`financial_fields` 保存原字段、标准别名、来源表、说明、单位、缺失率、映射版本以及候选平台字段。单位未查证时只归档，不开放为核心研究字段。

| 核心字段 | 原字段 | 口径 |
| --- | --- | --- |
| `revenue_ytd` | 营业收入 | 年初至报告期末累计流量 |
| `net_profit_ytd` | 净利润 | 累计流量，不能与归母净利润混用 |
| `parent_net_profit_ytd` | 归属于母公司所有者的净利润 | 归母累计流量 |
| `operating_cashflow_ytd` | 经营活动产生的现金流量净额 | 直接法累计流量 |
| `total_assets` / `total_liabilities` | 资产总计 / 负债合计 | 报告期末存量 |
| `parent_equity` | 归属于母公司所有者权益合计 | 归母权益存量 |
| `far_total_assets` | 财务指标文件_总资产 | 单独来源，不能覆盖资产负债表字段 |

财报期末不等于可用日期，差错更正日期不等于首次公告日期。各来源分别保留报表类型，默认历史查询只取 `A` 类合并报表；一个来源的公告日不能借给同一合并行中的其他来源。只有日期证据时，取公告之后的下一交易日 09:30，时区为 `Asia/Shanghai`。

目前这些最终整理值缺少首次披露及后续修订的历史版本证据，`strict_usable=false`。严格模式返回零条可用记录是预期结果。年度控制变量的 `marketvalue` 不能替代每日总市值，`everSTPT` 不能过滤历史股票池，实收资本金额不能当作股数。

## 查询

本次可直接使用下列快照；后续新导入则填入新的快照编号。严格历史查询：

```bash
FINANCIAL_SNAPSHOT=20261005-135042-6c91
~/envs/quant/.venv/bin/observe --root data data financial-history \
  --snapshot "$FINANCIAL_SNAPSHOT" --table financial_quarterly \
  --fields revenue_ytd,net_profit_ytd,total_assets \
  --instruments 000333.SZ,600519.SH --decision-time '2024-06-28 16:00'
```

探索查询必须明确滞后假设，例如 `--mode exploratory --lag-days 120`。这表示对缺少来源可用日期的记录，假设报告期后 120 个自然日，再从下一交易日起可用；它不能消除最终修订值的前视风险。查询结果同时返回覆盖、排除数量、来源和假设。本次实测美的集团、贵州茅台的净利润和总资产，在 2024-06-28 16:00 严格查询返回 0 条，120 天滞后探索查询返回 4 条。

读取最终整理值或控制变量进行数据检查，使用归档接口，按列投影以避免加载全部大表：

```python
from observe.data.financials import read_financial_archive
from observe.data.store import Store

root = "data"
snapshot = "20261005-135042-6c91"
dictionary = Store(root).load("financial_fields", snapshot)
print(dictionary[["table", "column", "standard_name", "unit", "missing_rate"]])

annual = read_financial_archive(
    root, "financial_annual", snapshot,
    instruments=["000333.SZ"], start="2023-01-01", end="2023-12-31",
    columns=["instrument", "report_period", "net_profit_ytd", "source_sha256", "source_row"],
)
controls = read_financial_archive(
    root, "company_controls_annual", snapshot,
    instruments=["000333.SZ"],
    columns=["instrument", "report_period", "marketvalue", "source_sha256", "source_row"],
)
```

归档接口不做历史可用性过滤，不能直接把返回值接入历史信号。代码使用 `query_financial_history` 查询决策时点可见记录；需要单季、TTM 或同比时，设置 `latest=False` 保留历史报告期，再把返回的 `data` 传给 `derive_periods(data, field, operator)`。算子只处理明确登记的累计流量，缺期不补零，资产负债存量不累加，派生可用时刻取全部输入的最晚时刻。

## 文件位置与当前限制

- `data/std/financial_*`、`data/std/company_controls_annual/`：不可变标准分区。
- `data/raw/external_financials/<import_id>.json`：输入指纹、发布凭据与归档字节校验。
- `data/audits/financials/<import_id>.json`：覆盖、字段、异常、公告日期及证券映射审计。
- `data/catalog/financial-fields-<import_id>.json`：字段字典 JSON 副本。
- `data/staging/financials/<import_id>/`：分块中间文件、冲突和隔离记录。

现有规则策略的 BP、EP 来自日线 `pb_mrq`、`pe_ttm`，不会因导入财务表自动改用最终财报值。本地声明式规格也只开放其登记的价量和估值字段。接入新财务因子前，需要明确来源、单位、报表类型、版本证据以及决策时点过滤，不能凭同名字段直接映射聚宽财务接口。
