## 二、按本项目模块归纳

### 1. 数据层

**BaoStock「按日期取全市场」**（`baostock/security/history.py` 的 `query_daily_history_k_AStock`、
`baostock/evaluation/season_index.py` 的 `query_daily_adjust_factor`）：一次请求拿到某天全市场的日线（含停牌标记、ST 标记、估值），
以及当天发生除权的股票清单。本项目的日线初始化和每日增量都走这条路，而不是逐只股票下载。

**BaoStock 的证券清单与全市场日线都是时点数据**：`query_all_stock(day)` 实测 2005 年的清单包含后来退市的股票；按日期取的全市场日线同样包含当天停牌和后来退市的股票，且行数与当天证券清单一致。历史股票池直接以全市场日线为底（证券清单只作核对），不用今天的股票列表倒推过去。

**vnpy 的研究目录**（`vnpy/alpha/lab.py`）：日线、分钟线、指数成分、数据集、模型、信号分目录存放，一个目录就是一个研究工作区。
本项目借这个思路划分 `data/` 目录；但 vnpy 是「一只股票一个文件」，全市场横截面读取慢，本项目改为按时间分区、一个分区包含全市场。

**qlib 的时点数据（PIT）**（`qlib/data/pit.py`）：财务数据同一报告期允许多个版本，查询时只取查询时点已经公布的版本。
本项目的财务表照这个口径设计字段；第一版不启用财务因子。

**存储方案对照**：qlib 用每证券每字段一个二进制文件，zipline 用列式文件存行情、SQLite 存复权和证券信息，rqalpha 用 HDF5 数据包，vnpy 用可替换的关系/时序数据库，vnpy.alpha 用每证券一个 Parquet。本项目取 zipline 的「大表列式文件 + 小表 SQLite」结构，文件格式换成 Parquet、按时间分区，查询用 DuckDB。详见 `02-决策记录.md` 第 5 条。

**不学**：qlib 的自定义二进制存储格式（换成 Parquet，好查、好对账）；free-stockdb 的本地 C++ 服务作为本项目的存储层（闭源、需要额外进程）；它若通过审计，只作为「外部导入」的一个数据来源。

### 2. 因子与表达式

**zipline 的因子流水线**（`zipline/pipeline/engine.py` 里的 `extra_rows`、`zipline/pipeline/term.py` 的 `window_safe`）：
每个因子声明自己需要回看多少个交易日，引擎据此自动往前多读预热数据；只有与复权方式无关的数据（收益率、比值）才允许再做滚动窗口运算。
本项目的因子注册表照此设计：每个因子写明「回看天数」和「是否窗口安全」，分段计算和全量计算的一致性靠它保证。

**vnpy 与 polars_ta 的算子分层**（`vnpy/alpha/dataset/ts_function.py`、`cs_function.py`；`polars_ta/wq/`）：
时间序列算子（按单只股票沿时间算，如 `ts_mean`）与横截面算子（按同一天全体股票算，如 `cs_rank`）命名上就分开。本项目沿用这种分层和命名风格。

**qlib 的 Alpha158**（`qlib/contrib/data/loader.py`）：因子按「K 线形态、价格、成交量、滚动统计」分组组织，窗口取 5/10/20/30/60。
本项目第一批因子参考它的分组方式，但只挑有明确解释的二三十个，不整套搬。

**不学**：vnpy 用 `eval` 直接执行公式字符串（`vnpy/alpha/dataset/utility.py` 第 252 行）。本项目用 Python 语法树解析，
只放行白名单里的算子名、字段名、数字和四则运算。

### 3. 标签、切分与预处理

**qlib 的两套预处理**（`qlib/data/dataset/handler.py` 的 `DataHandlerLP`：`learn_processors` 与 `infer_processors`）：
训练用的数据可以删掉标签缺失的行、做标签标准化；推理用的数据不能依赖标签。有参数的预处理器（均值、标准差）只在训练区间拟合。
本项目的数据集构建照这个思路分「训练视图」和「推理视图」。

**qlib 的横截面预处理器**（`qlib/data/dataset/processor.py` 的 `CSZScoreNorm`、`CSRankNorm`、`RobustZScoreNorm`）：
横截面标准化只用当天的截面数据，不需要拟合；稳健标准化用中位数和绝对中位差。本项目只实现其中三四个最常用的。

**skfolio 的带隔离期交叉验证**（`skfolio/model_selection/_combinatorial.py` 的 `purged_size`、`embargo_size`）：
训练集和测试集之间空出若干天，防止持有期标签跨越边界造成泄漏。本项目的滚动切分直接按「标签成熟时刻」比较时间，
效果等价于自动算出的隔离期，不需要人工指定隔离天数。

**PyBroker 的 `lookahead`**（`pybroker/strategy.py`）：同一问题的另一种处理，只作对照。

### 4. 组合构建

**qlib 的 Top-K 换仓策略**（`qlib/contrib/strategy/signal_strategy.py` 的 `TopkDropoutStrategy`）：
持有 K 只，每期最多换掉 n 只最差的，用最新排名最靠前的补上；有最少持有天数。本项目的「排名缓冲」和「最大换出数」直接对应这两个参数。

**hikyuu 的组件拆分**（`hikyuu_cpp/hikyuu/trade_sys/` 下的 selector、allocatefunds、moneymanager 等十余个组件）：
一个组件只做一件事。本项目只拆三块：**选股**（分数 → 候选名单）、**定权重**（候选 → 目标权重）、**生成订单**（目标 → 订单意图），不拆更细。

### 5. 回测账本

**rqalpha 的股票持仓**（`rqalpha/mod/rqalpha_mod_sys_accounts/position_model.py` 的 `StockPosition`）：
- 当日买入的股数记为「今日不可卖」，日终结算清零，实现 T+1；
- 除息日把「（到账日，金额）」放进应收分红队列，到账日才转成现金，净值里计入应收；
- 送转在开盘前按比例调整股数和成本；
- 吸收合并时旧代码持仓按换股比例转成新代码。

本项目账本的持仓结构照这四点设计。

**zipline 的分红处理**（`zipline/finance/ledger.py` 的 `earn_dividends` / `pay_dividends`）：按到账日分组的未付分红，与 rqalpha 思路一致，作交叉印证。

**rqalpha 的税费**（`rqalpha/mod/rqalpha_mod_sys_transaction_cost/deciders.py`）：印花税以 2023-08-28 为界从 0.1% 调到 0.05%；
最低佣金按「一笔订单」收取一次，部分成交不重复收。本项目的费用规则表按生效日期存储，思路相同。

**rqalpha 的撮合拒单**（`rqalpha/mod/rqalpha_mod_sys_simulation/matcher/base.py`）：买单遇涨停、卖单遇跌停拒单并写明原因。

**backtrader 的订单状态**（`backtrader/order.py`）：已创建、已提交、已接受、部分成交、全部成交、已撤销、已过期、已拒绝。
本项目的订单状态取其中适用于日频的子集。

本轮复用记录：本地 `repo/backtrader` 实际提交 `b853d7c90b6721476eb5a5ea3135224e33db1f14`，阅读 `backtrader/order.py` 的 `OrderData.add`/`addbit` 及其订单状态测试；采用行为参考，observe 保留自己的撮合器，并用 `tests/unit/test_ledger.py::test_participation_requires_reference_and_records_partial_fill` 验证部分成交、剩余数量和拒绝状态。

**不学**：
- rqalpha 用「成交当根 K 线的成交量」限制成交数量——日频回测里这等于偷看当天数据。本项目用决策前已知的历史平均成交额限制。
- rqalpha 退市时默认按最后市值退还现金——本项目把这种持仓标为「未解决」，正式评价被阻断，而不是假装卖掉。
- PyBroker 的动态选股会在股票离开选择窗口时自动平仓，且没有 T+1、整手、分红送转——这是本项目不用它当引擎的直接原因。

### 7. 数据源接入的踩坑经验（来自实测，详见 `01-数据源实测报告.md`）

- BaoStock 0.9.4 的 `get_data()` 在结果翻页时调用了 pandas 2.0 已删除的方法，必须自己逐行读结果集。
- BaoStock 匿名登录在服务端共享会话：另一个进程登出，会把正在下载的进程一起踢下线。全机只能有一个 BaoStock 下载进程。
- 东方财富接口不带浏览器请求头会被直接断开；带上后也会对大请求断开连接。只作日线交叉核对，不作主源。
- 通达信服务器的 K 线和实时行情接口已不可用，历史逐笔、历史分时、除权除息仍可用；已退市股票拿不到分时和逐笔。
