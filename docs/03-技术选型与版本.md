# 技术选型与版本

本文件记录**实际装过、实际跑过**的版本，以及每个选择的理由。没有验证过的写明「待验证」。
验证机器：Windows 11 Pro（10.0.26200），Intel i5-14400F（10 核 16 线程），内存 32 GB，D 盘剩余约 259 GB。验证日期 2026-09-28。

## 一、Python 环境

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 环境位置 | `D:\envs\quant`，uv 项目方式管理（`pyproject.toml` + `uv.lock`） | 与你其他环境（`D:\envs\lambda` 等）同一套做法；不用 `uv venv` / `python -m venv` 手建 |
| 解释器 | `D:\envs\quant\.venv\Scripts\python.exe` | 所有脚本、测试、后端服务都用它 |
| Python 版本 | **3.12**（本机 3.12.11） | 见下 |
| 项目安装方式 | 在 `D:\envs\quant` 里执行 `uv add --editable D:\projects\observe`，把本项目以可编辑方式装进环境 | 改代码立即生效，依赖只在一个地方声明 |

**为什么是 3.12 而不是 3.14**：3.12、3.13、3.14 三个版本上整套依赖都能解析通过；但本机 uv（0.8.22）只认识 3.14 的候选版（rc3），
要用 3.14 正式版得先升级 uv 本身。3.12 的二进制包覆盖最全，BaoStock、mootdx 这类多年没大更新的纯 Python 包在 3.12 上风险最小。
以后想升 3.14，重跑一遍 `scripts/probe/` 下的三个探测脚本和离线测试即可判断。

## 三、兼容性问题（实测发现）

1. **BaoStock 与 pandas 2.0 及以上版本不兼容的一处**：`ResultData.get_data()` 在结果超过一页时调用了 pandas 2.0 已删除的 `DataFrame.append`
   （`baostock/data/resultset.py` 第 146 行），长历史查询全部报错。**处理**：本项目的 BaoStock 适配器不用 `get_data()`，
   用 `rs.next()` + `rs.get_row_data()` 逐行读取后自己拼表。不改第三方包、不降 pandas。
2. **AKShare 在 pandas 3 下**：本次探测用到的新浪、腾讯、交易所清单、分红、日历接口都正常返回，未见不兼容。
3. **本机代理**：系统和环境变量都设置了 `127.0.0.1:7897` 代理。国内行情站点不应走代理，本项目的网络请求一律显式关闭代理
   （requests 传 `proxies = {'http': None, 'https': None}`，或设置 `NO_PROXY`）。
4. **Windows 控制台编码**：BaoStock、mootdx 的中文提示在默认控制台里是乱码，不影响数据；日志统一写 UTF-8 文件。

一个进程、一个端口就能跑起来。
