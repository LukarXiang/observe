**版本：V1.0 · 编制日期：2026-09-27**  
**定位：个人自用、研究优先、单机轻量、结果可复现**  
**读者：项目所有者、开发 Agent、后续代码审查者**

## 0. 给开发 Agent 的执行摘要

### 0.1 项目要解决什么问题

建设一套个人使用的 A 股量化研究项目，将免费数据接入、本地存储、股票池管理、因子计算、因子筛选与挖掘、机器学习、选股配置、历史回测和评价留档连成完整流程。用户已有数据分析与机器学习建模经验，希望把时间用于提出与验证研究假设，而不是维护复杂平台或反复编写下载、清洗和回测脚本。

完整不等于一次性安装很多框架。项目采用自己的普通 Python 仓库组织业务；复用成熟库的局部能力；统一数据表和配置是各模块之间的接口。不建设微服务体系，不 fork 多套完整平台，不要求前后端、分布式任务或实盘交易系统才能开始研究。

### 0.2 已确认需求与设计默认值

| 事项 | 已确认需求 | 本文给出的可修改默认值 |
| --- | --- | --- |
| 使用方式 | 个人自用、非商业；完整但轻量 | 单用户、单机、命令行与 Notebook；无需服务器常驻 |
| 市场与数据 | 免费 A 股数据；希望覆盖广、支持较高频率 | 先验收沪深普通股票日频；5 分钟进入完整第一版；北交所独立验证后启用 |
| 研究内容 | 选股、因子挖掘、机器学习、回测评估 | 横截面多股票建模，日频信号，按交易日周期调仓 |
| 模型 | 可扩展、便于研究和比较 | Ridge 与 LightGBM；不以深度学习作为启动前提 |
| 高频含义 | 用户希望有分钟级等高频数据 | 首先用于生成日内统计特征；不默认开展高频交易或完整逐笔研究 |

| 资金与策略 | 未指定真实投资资金及风险参数 | 仅模拟资金、现金多头、不加杠杆；不代表投资建议 |

### 0.3 不可破坏的开发约束

数据先保存本地再用于实验；一次实验固定数据版本、股票池、标签、因子、模型和回测规则。训练输入只能使用决策时点可获得的信息；训练标签必须在模型模拟拟合时点已经成熟。预测分数、目标仓位、订单、实际成交分开保存。

所有行情返回都需要检查历史范围、字段含义和质量。缺数据不能变成“没有信号”，抓取失败不能变成“该股票不存在”，零值占位不能变成有效开盘价。股票从候选池退出，不代表原持仓可以立即成交退出。回测费用、可卖数量、价格限制、分红送转与数据末端行为必须显式处理。

第一轮工作先完成数据源和回测引擎的小型可行性验证；先证明账本正确，再追求收益。样本不足或外部接口不可用时，保留已完成的离线流程，准确报告限制，不伪造真实数据，不无限更换框架。

## 1. 项目背景、目标与成功标准

### 1.1 背景与现有问题

零散量化脚本通常把下载数据、计算因子、训练模型、选股和回测写在同一个程序中。更换一个数据源或调仓规则时，其他部分容易跟着变化；最终即使净值不同，也难以解释改善究竟来自新信息、交易口径变化还是数据错误。

本项目需要把研究对象和研究过程沉淀下来：一个因子能重复计算，一组预测可以反复用于不同组合规则，一个历史实验能够恢复原始配置和输入。用户需要的是可持续迭代的研究工作台，不是展示功能很多但难以核对的演示系统。

### 1.2 核心目标

形成从原始数据到研究结论的完整闭环；让不同策略在相同条件下比较；能定位异常收益来自哪一天、哪只股票和哪笔成交；支持从少量证券扩展到更大历史股票池；后续可自然增加分钟因子、公式搜索和仓位优化。

系统成功标准是流程可运行、结果可复现、时间边界正确、资金账本可核对、增量效果能被客观评价。盈利、正 IC 或跑赢指数都不是软件验收的硬性条件；没有效果的研究也应输出完整、可信的负结果。

### 1.3 典型使用场景

**验证单因子。** 用户新增一个量价公式，指定股票池、历史区间和未来收益标签，得到覆盖率、分组表现、每日排序相关性、换手与分期稳定性。

**比较特征与模型。** 使用完全相同的数据和切分，比较基础因子、增加分钟因子、Ridge 与 LightGBM，保存样本外预测和成对差异。

**比较选股规则。** 不重新训练模型，直接读取同一份预测，改变选股数量、调仓间隔和保留缓冲，观察成本后收益、回撤和持仓变化。

**重复实验。** 指定已有实验编号，读取被冻结的数据清单和配置，在离线环境重跑；外部数据接口变化不应悄悄改变旧实验。

## 2. 范围划分与实施边界

### 2.1 两个交付层次

**最小闭环版本**：离线测试数据和一条真实日频流程可运行，具备股票池、基础因子、单因子分析、Ridge/LightGBM、样本外预测、等权选股、受约束回测和实验留档。

**完整第一版**：在日频闭环基础上，完成免费数据增量更新、历史股票池与质量审计、5 分钟接入与日频聚合特征、有限因子筛选、统一对照报告。5 分钟数据能力是完整第一版目标，不应被永久搁置；无法获得足够历史时，交付真实覆盖清单和可持续归档能力，不能声称已经完成多年全市场分钟研究。

### 2.2 功能优先级

| 优先级 | 本次范围 | 完成含义 |

| 第一版补全 | 免费数据更新、5 分钟特征、因子去重和前向筛选、对照研究 | 构成完整第一版，允许分阶段交付 |

不因用户个人自用而开展冗长的商业许可证比较；仍保留引用来源、原有署名和接口限频信息。不得绕过鉴权、风控或使用来源不明的密钥。

## 3. 总体流程与关键对象

### 3.1 一条完整的研究链路

```text
数据源下载 → 原始记录 → 标准化与质量检查 → 数据版本
                                             ↓
历史股票池 + 当时可用信息 → 因子与标签 → 时间切分
                                             ↓
                         因子评价 / 筛选 → 模型训练
                                             ↓
                                  样本外预测分数
                                             ↓
                             选股与目标仓位计划
                                             ↓
                       交易规则 / 成交 / 持仓 / 资金
                                             ↓
                         评价报告 + 实验清单 + 复现
```

因子评价与模型训练共同读取同一份标签，不得各自计算不同口径的未来收益。回测只读取冻结预测和市场数据，不临时联网、不重新训练。可视化只读取已经保存的结果，不隐藏执行额外的金融计算。

### 3.2 必须区分的对象

| 对象 | 含义 | 不能混淆为 |
| --- | --- | --- |
| 因子值 | 特定证券、特定决策时点的一个可计算特征 | 已验证有效的投资信号 |
| 预测分数 | 模型对证券的排序或收益预测 | 可以直接交易的收益率、已成交订单 |
| 目标仓位 | 策略希望持有的权重或数量 | 实际持仓 |
| 订单意图 | 某时刻提出的买卖请求 | 一定能成交的交易 |
| 成交记录 | 按模拟规则实际发生的成交 | 理想化按排名全部换仓 |
| 持仓与净值 | 由真实模拟账本逐步累计的状态 | 因子分组收益的直接拼接 |

### 3.3 示例时间约定

默认研究配置：交易日 D 的收盘数据确认可用后，生成日频因子与分数；最早在下一交易日的指定成交事件执行。不能用 D 的收盘价形成信号，再把成交记在 D 的收盘价。

“收盘确认可用”不是假设所有网站在收盘瞬间已经更新。数据层维护可用时间或保守延迟假设，实验报告写明该假设。默认按交易所日历移动日期，不用自然日加一代替下一个交易日。

## 4. 技术架构与轻量化原则

### 4.1 推荐技术组合

| 层次 | 默认选择 | 约束 |
| --- | --- | --- |
| 语言与依赖 | Python；pyproject.toml 与锁文件 | 先验证兼容性，再锁定真实成功版本 |
| 数据计算 | pandas、NumPy | 首期只保留一种主要 DataFrame 计算方式 |
| 文件存储 | Parquet + JSON/YAML 清单 | 大表不以 CSV 为唯一存储；CSV 主要用于人工导出 |
| 元信息 | 本地文件；必要时 SQLite | 不先部署数据库服务 |
| 查询加速 | DuckDB 可选 | 只有本地分析查询成为瓶颈时增加 |
| 模型 | scikit-learn、LightGBM | Ridge 和 LightGBM 先形成稳定对照 |
| 回测 | PyBroker 适配层，先做能力验证 | 只有一套权威回测结果；禁止双重资金账本 |
| 分析报告 | Alphalens-reloaded、QuantStats、Matplotlib | 报告库可作为可选依赖，不影响核心数据和训练 |
| 测试与入口 | pytest、命令行、少量 Notebook | Notebook 调用包内函数，不复制核心实现 |

这里是本项目技术建议，不是各库已经在同一环境通过安装测试的声明。Agent 必须记录 Python、操作系统、依赖锁定版本及兼容性检查结果。

### 4.2 模块边界

保留 data、universe、features、labels、research、models、portfolio、backtest、evaluation、experiments 十个清晰模块。它们属于同一个 Python 包，不是十个服务。简单纯函数优先，仅在数据源、模型和回测器这些真正可替换的位置设置接口。

数据量较大时按时间分区读取和计算，不先构建分布式任务平台。只在性能测量显示必要时增加缓存、并行或替换底层计算库。禁止为未来假想场景提前设计通用插件市场、可视化拖拽工作流和复杂依赖注入框架。

### 5.2 具体阅读位置

Qlib 优先阅读 `qlib/contrib/data/handler.py` 中的 Alpha158、DataHandlerLP 文档、LightGBM 工作流配置和 TopkDropoutStrategy。重点理解特征定义、可拟合预处理、训练区间、预测和策略如何分离，而不是复制全部模型。[R01][R02][R03]

PyBroker 优先阅读 `StrategyConfig`、订单与持仓结果、费用回调、自定义数据源和 `walkforward_split`。本项目自己生成滚动切分和样本外预测，默认不同时使用 PyBroker 的训练切分，防止边界重复处理。当前文档中费用和持仓逐日记录需要显式配置，不能依赖默认值。[R05][R06]

Alphalens 使用预先构建的统一未来收益表接入，而不是让其默认工具重新按收盘价计算标签。QuantStats 接收已对齐的日收益和基准，不负责改变成交或填补丢失交易日。[R07][R08]

## 6. 数据源接入与更新需求

### 6.1 来源分工与能力等级

默认先实现 BaoStock 与 AKShare 两个历史适配器；腾讯快照后续增加。BaoStock 是历史行情候选，不预先承诺某个统一的分钟起始年份；实测失败可使用已核验的其他入口，但需要记录来源变化。[R09]

AKShare 某些分钟入口只保留近期数据；当前文档明确 `stock_zh_a_hist_min_em` 的 1 分钟返回范围为近 5 个交易日且不复权，还提示部分历史开盘字段可能为零。因此系统不能只按返回行数判断“完整 OHLC”，必须按字段核验并标注可用能力。[R04]

腾讯/easyquotation 只作为行情快照入口；快照、成交明细、分钟线和完整逐笔委托分别建类型。快照的累计成交量不能直接当作这一采样间隔的成交量。[R10]

用户此前说的 FreeDB 尚未确认具体仓库，本文件暂对应 `hello245m/free-stockdb`。其更新器文档说明需要单独配置数据镜像，当前示例配置不构成可用历史数据供应承诺。[R16]

### 6.2 每个适配器必须提供的功能

提供能力查询、证券列表、日历、行情下载、增量更新和质量摘要；某源不支持的能力明确返回“不支持”，不能返回空表伪装成功。财务、行业、股本、复权和公司行动允许单独适配，不要求单个数据源包办全部内容。

每次请求记录来源、上游网站、接口、参数、请求时间、响应状态、返回范围、记录数、客户端版本和错误信息。同一上游经不同 Python 包访问，不能记成两个独立的数据来源。

### 6.3 能力清单与接入验收

| 字段 | 内容 |
| --- | --- |
| 数据类型与频率 | 日线、5 分钟、1 分钟、报价快照分别声明 |
| 请求范围与实际范围 | 请求起止、真实最早和最新记录、是否被服务端截断 |
| 覆盖对象 | 沪市、深市、不同板块、上市与退市证券的实际覆盖 |
| 字段级质量 | 开高低收、成交量、成交额是否有效；哪些字段是占位或推导值 |
| 时间与单位 | 时间戳是区间开始还是结束；时区；成交量是股还是手 |
| 历史可信程度 | 原始历史版本可证实、基于合理延迟假设、只拿到当前修订版 |
| 更新约束 | 频率限制、刷新时间观察、错误比例、已验证日期 |

接入验证使用一组固定样本：沪深代表证券、不同上市时期、短历史、停牌和退市情形。不能只测当前活跃的大市值股票。选择覆盖样本不是投资推荐；样本代码由 Agent 按实际数据确定并保存。

### 6.4 下载、重试与失败恢复

默认低并发，尊重上游限频；使用有限次数指数退避和请求超时。单个分区下载后先写临时文件，通过校验再原子替换；只有实际成功提交的分区才能推进更新进度。重复执行相同任务不得产生重复行。

增量更新允许回看最近若干交易日以捕获修订，但旧文件需要通过版本清单可追溯。历史更改不得覆盖已冻结实验的输入。一次请求部分成功时保存成功分区和失败列表，整体状态为 partial，不得显示全量成功。

离线模式禁止网络访问。接口不可用时默认使用指定的已有版本并明确标注滞后；不得悄悄切源、混合复权口径或自动用模拟数据替代。

### 6.5 归档与数据质量规则

日线先建立稳定历史，5 分钟优先对同一研究股票池验证历史深度；近期 1 分钟按需持续归档。下载水位不足必须在运行前提示。真实数据完整性按证券、日期、字段统计，不能仅以平均缺失率掩盖某一时期系统性缺失。

禁止无条件补零和后向填充。停牌导致缺少成交与接口漏数分开处理。分钟聚合不能跨午间休市、跨交易日补连续时间；集合竞价记录的纳入方式单独声明。不同来源的分钟数量可能因区间和竞价定义不同而不同，不能统一硬编码“每天必须相同根数”。

## 7. 数据标准、版本与历史股票池

### 7.1 统一标识与字段

证券使用稳定的内部 `instrument_id`，对外保留 `000001.SZ`、`600000.SH` 一类包含市场的代码；原始代码映射保存在适配器中。不能仅用六位数字区分股票与指数。股票改名不产生新证券；代码复用、上市与退市历史要保留映射。

项目业务时区统一为 `Asia/Shanghai`。时间字段使用带时区的明确时间语义，持久化可以统一 UTC，但转换必须可逆；交易日期单独存储。适配第三方库需要无时区时间时，只在适配器中转换，并以测试确认没有偏移。

价格单位为人民币元，成交量标准单位为股，成交额单位为人民币元，收益率采用小数而非百分数。所有原始单位及换算规则随数据版本保存。浮点数用于研究计算；资金账本使用明确的金额精度、舍入规则与对账容差。

### 7.2 不混淆四类时间

| 时间字段 | 含义 | 示例用途 |
| --- | --- | --- |
| event_time / period_end | 事件发生或报告期结束 | 某根 K 线结束、某份季报统计期末 |
| source_published_at | 来源公布该信息的时间，可能未知 | 财报公告或修订发布时间 |
| available_at | 模型允许使用该记录的最早时刻 | 公告时间加必要处理延迟，或明确的历史假设 |
| ingested_at | 当前系统实际下载时间 | 审计抓取与数据版本，不直接等于历史发布时间 |

历史数据今天下载，不代表历史上全部不可用；也不能因为数据对应 2020 年就宣称当时拿到的就是今天的修订版。缺少可证实的历史发布时间或修订记录时，使用 `availability_quality` 标明 `verified`、`assumed` 或 `unknown`。严格回放排除关键未知字段，探索性研究允许显式降级并在报告中披露。Qlib 的 PIT 设计可作为概念参考，但本项目不照搬其二进制存储。[R03]

### 7.3 标准表与主键原则

核心表包括证券主数据、交易日历、行情、历史状态、公司行动、股票池成员、财务与行业版本、因子、标签、预测、目标仓位、订单、成交和净值。字段细节见附录 A。

每张表声明主键、非空字段、排序、单位和版本。行情标准层的一个数据快照内，同一证券、频率和区间结束时刻只有一条被采用记录；多来源原始记录可以并存，但采用规则必须固定，不逐单元格随意拼接来源。

### 7.4 股票池的三层区分

**历史存在池**：在当时已经上市、尚未退出相应市场的证券，来自历史证券主数据，不能由当前列表倒推。

**研究候选池**：根据当时已知的信息过滤得到，如上市时长、历史流动性、风险警示状态、行业和数据基本可用性。

**成交可行性**：在具体交易事件才检查的停牌、价格限制、可卖数量等约束。次日不能成交的事实不得提前用于前一日排序或剔除候选。

默认先覆盖已验证的沪深普通股票，板块开关可配置；缺乏有效交易规则和历史状态的板块不自动开启。研究规则可以排除当时已知的 ST 状态，但不能用今天的 ST 标记修改所有过去的候选池。

### 7.5 避免幸存者与事后筛选

不能使用当前指数成分回测整个历史，也不能提前删除未来将退市、未来停牌或未来有数据缺口的股票。历史成分确实拿不到时，选择可解释的历史规则池；仍存在退市证券缺失等问题时，将研究标记为受限样本，不以“全 A 股”对外描述。

数据完整性报告可以事后统计，但不得通过“全区间一直有数据”过滤得到回测候选池。用于开发的小样本固定代码允许用于工程测试，却不能被包装成无偏的全市场收益证据。

### 7.6 价格、复权与公司行动

原始成交价用于订单、成交、费用和可交易判断；用于跨期特征与标签的连续价格序列单独保存，带复权方法和版本。不得用复权价格与真实股数直接计算现金账本。

特征计算尽量使用回报、比例等可解释变量；涉及复权时只纳入决策时点已生效的信息。今天重新下载的前复权序列可能改变历史绝对价格，不能不留版本就覆盖旧特征。不同调整算法是否影响某个比例因子，需要实际校验，不能把“所有复权都泄漏”或“比例一定无影响”写成未经检验的规则。

回测必须处理送转/拆并股、现金分红、应收权益与实际到账时点。除息时确认应收权益、到账日增加可用现金，二者不能重复增加资产。已持仓证券遇到不支持的配股、合并或退市结算事件，应停止正式可交易评价或标记为未解决，不得把该持仓从账本删除。

## 8. 因子计算与分钟特征

### 8.1 因子注册与版本

每个因子定义包含：名称、版本、说明、公式/函数、原始字段依赖、数据频率、回看窗口、最小有效观测数、可用时间规则、输出单位、缺失处理、适用股票池和代码摘要。

因子计算函数不下载数据、不训练模型、不决定持仓。相同定义和同一数据版本重复计算应得到相同结果。缓存键至少包括因子定义、数据清单、股票池/横截面范围和处理器版本；修改其中任一内容必须使相关缓存失效。

### 8.2 第一批因子建议

第一批约 20—40 列，属于建议规模而非硬性指标。先做少量有明确解释的窗口组合，不直接复制几百个特征。

| 因子类别 | 初始例子 | 实现要求 |
| --- | --- | --- |
| 趋势与反转 | 过去 5/20/60 个交易日收益、短长均线比 | 标明区间端点；预热不足输出缺失 |
| 风险与振幅 | 滚动收益波动、日内振幅、下行波动 | 统一收益口径和自由度；窗口按交易日定义 |
| 量能与流动性 | 成交额相对历史均值、成交量变化、量价相关 | 统一股/手和金额单位，零成交与缺失分开 |
| K 线结构 | 实体占振幅、上下影线占比、隔夜缺口 | 分母为零时按规则处理，不制造无穷大 |
| 相对表现 | 相对基准收益、当日横截面排名 | 基准和横截面证券集合需要固定版本 |
| 基本面扩展 | 估值、盈利或财务变化 | 只有发布日期、单位和历史版本可解释后启用 |

这些是研究候选，不预设方向有效，也不承诺收益。Alpha158 可用于对照和公式组织参考，不等同于必须原样采用的因子名单。[R02]

### 8.3 时间轴和预处理

时序计算按证券分组，横截面计算按决策日期分组。停牌或缺行时先与交易日历对齐；“过去 20 个交易日”不自动变成“最近 20 条有成交记录”。最小有效观测比例、是否跨停牌使用历史价格明确配置。

模型需要的均值填补、缩放等有拟合参数的处理器，只在训练集拟合；训练、验证、预测统一复用。截面排名、当天去极值和当天横截面中性化可以使用当时已经可获得的全体候选特征，不使用当日未来标签；这一点与跨全历史拟合标准化参数严格区分。

保留原始因子与处理后因子的关系。滚动窗口缺失不是零；标签缺失不能补零；严禁以未来值后向填充过去的特征。

### 8.4 5 分钟进入日频研究的方法

完整第一版增加 5 分钟接入，但先把分钟信息聚合为日频特征，再与现有日频模型融合。这样可以直接检验分钟信息是否有增量，而不用同时改变模型类型与交易频率。

候选包括日内实现波动、上下行波动比例、早盘/尾盘收益、区间成交额占比、成交重心偏移、价格相对日内成交均价的位置，以及这些统计量的历史滚动变化。成交均价只有成交额与股数单位可信时才计算。

分钟特征必须保存覆盖比例和有效字段掩码。仅有收盘点、缺少真实开高低字段的数据只能生成相应点序列特征，不能伪造成完整 K 线。基于分钟涨跌与成交量得到的代理指标要命名为代理，不能宣称识别了真实主力买卖或逐笔主动方向。

第一版信号在收盘后形成，因此当天分钟统计可用时间为最后依赖数据可用之后；将来用于盘中信号时，未完成区间和当日未来分钟不得进入特征。

### 8.5 性能实现要求

优先批量、向量化、按时间分区计算。分区边界必须读取足够历史预热，但只写回本分区结果；全量计算与分区计算需要逐项一致性测试。只计算选定股票池和因子，不为一个小实验全量载入所有分钟数据。

## 9. 标签、数据集与时间切分

### 9.1 统一的未来收益标签

默认主任务是对未来持有期收益排序。标签定义与模拟成交约定对齐：在交易日索引 k 的收盘后形成信号，参考进入时点为 k+1 的开盘，参考退出时点为 k+1+h 的开盘，h 为持有的交易日间隔。

无公司行动的简化表达为：`y(k,h) = open[k+1+h] / open[k+1] - 1`。例如 h=5，退出位置是 k+6，不是 k+5。存在分红或拆股时，通过经过验证的公司行动调整计算同一持有区间的收益，不能直接用原始价比制造虚假亏损。

该标签是统一的研究参考收益，不保证每只股票都能按参考开盘成交。真实停牌、涨跌停和资金约束在回测处理；因子报告需要同时披露参考标签与实际组合结果的区别。

### 9.2 标签缺失与成熟时间

标签表保存进入/退出时刻、实际依赖的最晚数据可用时刻、是否有效和无效原因。标签只有在全部依赖已经可用时才可用于训练。不能仅凭样本特征日期早于训练截止，就把尚未完成的未来收益放进训练。

退出日没有有效报价时不自动移动到下一条可得行情，否则持有期被悄悄延长。需要延迟退出的研究必须是另一个明确命名的标签。因停牌、退市或公司行动不全产生的标签缺失单独统计；不得据此把原候选股票从回测持仓中事后清除。

### 9.3 一套切分计划贯穿全项目

切分器按决策日期生成训练、验证、测试窗口，同一天所有证券属于同一个窗口。默认采用滚动或扩展训练、固定长度测试块，不对全历史随机打散后做训练测试切分。

建议起点为约 504 个交易日训练、126 个交易日验证、63 个交易日测试，实际区间取决于数据覆盖。这些数字是可修改的工程起点，不是经过证明的最优设置。每个测试块开始前，保存该模型的模拟拟合截止时间及实际使用的样本清单。

训练标签成熟、训练/验证标签区间重叠与测试开始边界通过具体时间区间比较检查，不用“固定跳过 h 行”替代。不同证券缺行和 h+1 的交易延迟会使简单行数规则出错。PyBroker 的 lookahead 只作为实现参考，不替代本项目显式时间检查。[R05]

### 9.4 模型拟合与预处理的时点

区分 `fit_asof`（模拟历史拟合时刻）与 `executed_at`（现在真正运行程序的时刻）。当前运行可以重建历史模型，但其样本、特征版本和成熟标签必须遵守 fit_asof。实际运行时间不能被写成模型在历史上已经存在的证据。

超参数在开发验证窗口确定；可在模型配置冻结后，用截止测试前已成熟的训练加验证样本重新拟合，必须记录该次 refit。滚动过程中，过去的测试段在以后成为已知历史后可以进入后续训练，但不得反向修改已经保存的早期预测。

### 9.5 探索与最终留出

允许在一个明确的开发区间开展一次性因子筛选，避免第一版必须逐日期嵌套筛选的繁重流程。使用整个开发区间选出的名单，不能再将该区间内所有早期回放描述成当时已冻结名单的严格历史样本外结果。

最后保留一段未参与因子、参数、持仓规则选择的留出区间。若用户已反复查看该区间，就将其降级为开发区间，而不是继续标“最终样本外”。数据不足时可以交付探索结果，但报告必须说明证据级别。

## 10. 因子评价、筛选与有限挖掘

### 10.1 统一评价指标

每个决策日分别计算因子与标签的 Pearson IC 和 Spearman Rank IC，名称明确区分；汇总默认按日期等权，不让样本较多的日期自动占更高权重。有效证券太少、因子常数或标签常数时返回缺失，并记录原因。

输出覆盖率、缺失原因、分位组收益、分组单调性、头尾组差、分期 Rank IC、换手和与已有因子的相似度。Alphalens 用作分析实现参考及报告工具；其信息系数函数的口径应核对为 Spearman，不能同时又在报告中标作 Pearson。[R07]

### 10.2 因子分组不等于可交易组合

分位组存在大量并列值时，可以减少有效组数或采用确定的规则，并记录实际组数；不能随机打散制造组间差异。排序相同的证券以固定代码顺序保证可复现，但不把这种人为差异视为因子信息。

头尾组差是诊断统计，不代表本项目实际做空。h 日重叠收益不能按每天独立实现的策略收益直接连乘；实际净值必须来自持仓账本，或另行定义有资金分配的分批持有组合。

不使用未经说明的 sqrt(252) 将所有 ICIR 自动转成显著性结论；重叠标签和时间相关性存在时，至少报告原始每日序列、分段稳定性。需要置信区间时按连续日期块抽样，而不是把所有股票日期行当独立样本。

### 10.3 初步筛选流程

先做质量淘汰，再做重复性检查，然后做增量验证。质量淘汰检查缺失、常数、异常尖峰、仅少数日期有效等情况；重复性可用开发区间的平均每日相关性加公式结构检查；高相似不必自动删除，保留可解释的选择记录。

增量验证采用相同切分和相同模型：基础因子组，与加入一个候选组之后做成对比较。记录 Rank IC、前列股票表现、成本后组合收益、换手及分期差异。不能仅因某次特征重要性较低就判定无用，也不能仅因训练期重要性较高就晋级。

### 10.4 有限研究预算

默认每轮只研究一个问题；人工候选不超过 40 列、模型参数组合不超过 12 个，最终少量候选再跑 3 个随机种子。这些是控制工作量的建议值，可由配置修改。必须记录尝试次数、淘汰原因与失败实验，不只保存最好的结果。

没有稳定增量时停止扩张这一方向，保留负结果。不要用降低交易成本假设、缩短测试区间或删除困难证券的方法把无效因子“调好”。

### 10.5 自动公式挖掘的接入方式

gplearn 是后续候选生成器，输入已经对齐的基础变量和安全算子，输出待评价表达式；不直接生成正式策略。默认优化目标与本项目逐日横截面评价未必相同，需要适配和重新验证。[R12]

表达式以有限 AST 或算子树解析，不对外部字符串直接 eval。限制算子、深度、公式长度、执行时间和输出规模。候选生成使用开发数据，最终留出不参与生成或反馈。LLM 自动写代码与执行研究不在首期范围内。

## 11. 模型训练、预测与结果解释

### 11.1 基线与模型接口

基线包括不使用模型的单因子排序、固定因子等权得分、Ridge、LightGBM。前两项用于判断复杂模型是否真的增加信息，不需要接入额外框架。

默认跨股票训练一个横截面模型，而不是为每只股票分别建模。输入为日期×证券的因子矩阵，输出同一行对应的预测分数。日期、代码、来源标识用于索引，不默认作为可学习输入。行业类别、规模等只有在定义、可用时点和缺失处理明确后才加入。

模型接口暴露 fit、predict、save、load；保存特征顺序、预处理器、配置、训练日期、样本数、标签版本和依赖版本。推理发现必需特征缺失或顺序变化时直接报错，不静默补列后继续。

### 11.2 训练与权重

默认每个决策日总训练权重相同，同一天各证券均分该日权重；可配置为逐行等权，但实验比较中不能悄悄切换。缺失填补与数值缩放只在训练集拟合。LightGBM 早停只看开发验证集，最终留出不用于挑选迭代次数。

第一版不进行大规模超参数搜索。每轮保存全部参数结果，优先比较少量模型是否优于简单基线。随机种子、线程数和平台版本写入清单；跨平台无法逐位一致时使用明确的数值容差，并要求排序差异被报告。

### 11.3 样本外预测落盘

每个预测至少包含实验编号、模型编号、决策日期、证券、分数、模型 fit_asof、预测生成时间、标签版本、所属测试窗口和证据级别。

同一正式运行中，一个日期证券对只允许一份主预测；多模型或多种子作为不同 model_id 保存。预测阶段不需要未来标签；标签缺失只影响事后评分，不应导致预测样本提前消失。

### 11.4 解释与诊断

展示模型输入贡献的概览、重要特征、分期表现和失败案例。简单模型系数与树模型重要性可以先做；SHAP 等完整解释不是首期阻塞。所有解释只描述模型关系，不宣称因果。

模型评价以样本外排序能力和组合增量为主，MSE/MAE 为辅助。预测为横截面排名分数时，报告明确写“分数”而非预期收益率。拟合很好但换手成本抵消增益的模型，应允许被否定。

## 12. 选股、目标仓位与调仓

### 12.1 最简单的正式基线

默认使用 Top-N 排名选股、等权目标仓位、固定交易日间隔调仓。建议示例为选 20 只、每 5 个交易日调仓，均为可修改的研究参数，不是投资建议。并列分数按稳定规则排序。

设置总股票目标仓位、单股上限、最少候选数和可选行业上限。约束不可同时满足时优先保留现金，不能为凑满仓位临时放宽。目标上限约束的是新计划；因价格变化或被冻结持仓导致的被动超限必须记录，不能虚构成交消除。

### 12.2 候选、保留与换出

可选排名缓冲用于减少边界反复换仓，例如已有持仓仍处于 Top-(N+b) 时保留。b 是配置参数；缓冲、最大换出数量、最低持有期不能偷偷混成不同策略。

未入选的新证券不买入；原持仓退出研究池只形成卖出意图。停牌、跌停或未到可卖日时继续留在持仓账本，暴露与净值照常统计。分数缺失按预先规则处理并记录原因，不自动等于负无穷强制卖出。

### 12.3 从权重到订单

目标权重先结合决策时点已知资产、价格和现金形成数量或预算，不用下一交易日收盘价、最高价或全日成交量计算预提交订单。数量遵守适用的买卖单位和可卖数量规则。

跳空导致买入资金不足时，按固定优先级缩量或拒单；结果记录计划量、实际量、未成交原因和剩余现金。资金不足不自动产生借款。不可交易持仓占用的资产不得再次分配为可用现金。

默认订单只在指定成交事件有效，未成交或部分成交的剩余数量在事件后取消；不无限保留旧信号。下次调仓重新计算计划。需要跨日补单时必须单独配置有效期、撤单和重新检查规则，不能暗中持续追单。

### 12.4 仓位优化的后续入口

等权基线稳定后，才允许增加 skfolio 等约束优化。优化所用风险估计和收益估计只能来自决策前数据；任意模型分数不直接当作收益率输入。优化不可行时回到配置中的等权/现金策略，记录回退原因，不静默改变目标。[R13]

## 13. 回测引擎、交易规则与资金账本

### 13.1 PyBroker 能力探测是前置步骤

PyBroker 作为候选而不是未经验证的既定结论。Agent 必须用小型合成行情验证：冻结预测接入、下一事件成交、费用回调、可卖数量、冻结持仓、公司行动、原始价格现金账本和逐日持仓导出。

特别核查“证券不再有数据”和“动态股票池移除证券”是否触发隐式平仓。当前文档描述某些动态选择行为会关闭离开窗口的持仓，因此本项目不直接使用该选择器替代历史股票池管理。[R05]

需要持仓明细时显式启用记录；费用显式启用；退出价格与信号延迟显式设置；禁止以默认中间价作为未解释的成交假设。[R06]

若公开接口无法实现关键规则，不得只在报告上修补交易结果。提交一个简短设计决策，说明缺口，限定一轮替代评估。可保留 PyBroker 为研究近似器，但此时不能称为已验收的 A 股受约束账本；正式账本需由单一可测试实现承担。

### 13.2 规则按证券、市场与生效日期配置

规则表包含交易日历、时段、最小报价单位、买入单位、零股卖出、可卖释放时间、涨跌幅或有效价格上下界、停牌、上市初期例外，以及费用和税项的生效区间。

不得把所有 A 股固定写成同一涨跌幅、同一买入单位；历史回测也不能全程使用最新规则。例如上交所 2026 年交易规则自 2026-07-06 生效，主板风险警示股票相关规则存在调整，这说明时间版本是必要的数据，不是形式化要求。[R18]

开发时为实际启用的市场和区间核对相应交易所规则、暂缓实施条文及费用资料，保存来源和生效日期。本文不提供一张未经逐项核验的全市场现行规则常量表。未覆盖的证券/日期不能进入“规则已验证”模式。

### 13.3 默认成交模型与近似边界

默认研究成交基准是下一交易日开盘价加方向相关滑点，但仅为日线级成交近似，不保证真实集合竞价一定获得该价。买卖意图在前一日已形成，不能读取成交日全日高低价来决定是否提交。

已知停牌禁止成交；无法验证开盘有效价则不成交。没有盘口队列时，对处在不利价格限制边界的方向采用明确的保守拒单规则，并标记执行模型，不宣称精确还原涨跌停排队。

默认参与度上限依据此前已知的历史流动性计算，不使用次日全日成交量预先决定订单规模。使用成交区间实际成交量做事后容量诊断可以保留，但不能倒流影响前一时点决策。

日频首次实现采用保守的 `preopen_cash_only`：同一开盘事件提交的买单只使用事件前可用现金，不假设同一集合竞价尚未确认的卖出款已经可用。卖出资金可在后续允许的交易事件使用。需要更接近顺序卖出再买入的模拟时，以另一执行配置或分钟事件验证，不能把同一瞬间处理顺序当成已证实的真实机制。

### 13.4 每个交易日的事件顺序

先处理已生效公司行动和按规则解冻的可卖数量；读取前一决策时点已生成的订单；检查可交易状态、价格与资金；按确定顺序尝试成交；更新现金、持仓和应收权益；使用有效价格估值；收盘数据确认可用后再形成下一次决策。

成交、估值和因子计算读取的数据视图分开。停牌时允许用最近可用估值保留资产，但必须带 stale_price 标识；这不是可成交价格。异常退市或长期停牌资产不能无限按最后价格标成“无风险资产”，需要披露未实现风险和处置假设。

### 13.5 账本与公司行动

每日满足：`总资产 = 可用现金 + 冻结现金 + 持仓市值 + 应收权益 - 应付费用`。账本不能出现未解释的负现金、负持仓、超可卖数量或没有成交的现金变动。

拆股/送转测试例：100 股×10 元变为 200 股×5 元，忽略其他因素，总资产不变。现金分红测试例：100 股×10 元，除息后价格 9 元并形成 100 元应收权益，总资产仍为 1000 元；到账时只将应收转为现金，不再次增加收益。上述数值仅是合成测试，不代表某家上市公司事件。

不能既使用已经包含分红的复权收益更新资产，又在账本追加分红现金。税费、分红扣缴与配股认购等无法完整建模时分别披露；正式结果不得宣称已精确反映用户税后可实现收益。

### 13.6 数据末端、退市与错误处理

数据结束时默认按现有持仓估值，保留未平仓头寸；不自动在最后一根行情上卖掉所有证券。确需测试期末平仓时必须单独配置，并遵守当时可交易条件。

股票中途缺数据不能直接从资产计算中消失。关键原始价、公司行动或持仓规则存在无法解决的缺口时，正式回测状态为 blocked；探索模式可以继续并列出具体受影响持仓和日期，但不能与完全验证结果混排成一个“最佳策略”榜。

## 14. 评价报告、基准与增量判断

### 14.1 三层报告

| 层次 | 必须内容 | 主要用途 |
| --- | --- | --- |
| 因子层 | 覆盖、每日 IC/Rank IC、分组、分期、相似度、换手 | 判断因子是否提供可重复的区分能力 |
| 模型层 | 样本外预测、分期排序、基础/新增特征成对比较、误差与失败案例 | 判断建模是否带来真实增量 |
| 组合层 | 净值、费用、回撤、风险、现金占比、持仓、换手、未成交原因 | 判断交易约束后是否仍有价值 |

报告首页固定展示：数据版本、实际区间、股票池、标签、信号/成交时间、费用与滑点、执行近似、证据级别、缺失和未解决事项。不能只展示一条最漂亮的净值曲线。

### 14.2 基准和对照组

默认至少包含同股票池同调仓规则的简单等权基线、一个固定规则/单因子基线，以及一个覆盖一致的市场指数。指数是价格指数还是全收益指数必须标明；价格指数与含分红组合比较时不能隐去口径差异。

所有策略使用相同评估日历、资金起点、执行规则和成本配置。基准缺少日期时不能只按交集删除策略的亏损日；应修复基准或明确缩小共同评价区间，并保存缩小原因。现金策略或空仓区间继续保留交易日记录。

### 14.3 指标口径

净值按账本资产计算，日收益为相邻交易日净值之比减一。累计收益、最大回撤、年化收益、波动、Sharpe、主动收益与信息比率分别定义；不要将“策略年化减基准年化”与“主动收益序列的年化表现”混写为同一指标。

年化收益按明确的时间长度计算；波动与 Sharpe 的年化因子为配置参数，展示所用日历和无风险利率假设。默认无风险利率可设零作为研究约定，但必须显示。零波动、净值非正、样本过短等情形返回不可定义，不用零或无穷大参与排名。

换手至少保留交易额口径：当日买卖成交额之和除以前一日资产；如展示半换手另行标注。胜率区分正收益交易日比例和已闭合交易盈亏比例。实际交易配对方法（如 FIFO）明确配置，不从收益序列反推逐笔胜率。

### 14.4 成本与流动性分析

同时输出费用分项、滑点假设、不同成本情景、未成交率和未成交原因。一次净值结果对应一套明确成本与成交配置。若使用同一成交路径加回费用展示“费用前参考曲线”，标明它不是重新以零成本资金路径运行的结果。

可以比较基础成本与加倍成本等压力情景，但费率和个人佣金未确定时只使用“研究假设”名称，不称实际券商费率。成交量参与度和规模敏感性必须披露数据限制，不能凭日线模拟输出精确市场容量承诺。

### 14.5 增量判定方式

相同样本、切分和交易配置下，新因子/新模型需与既有基线成对比较。重点看多个时间段是否方向一致、是否过度集中于极少数股票、增加收益是否主要来自更多风险或更多换手。

不设一个通用的“IC 大于某数就有效”阈值。判断报告写明证据、限制和下一步，允许“没有证据表明新增模块更好”。软件通过验收并不等于策略值得投入真实资金。

## 15. 实验管理、可复现与缓存

### 15.1 每次运行形成独立记录

实验编号可以由日期时间、配置摘要和短随机后缀组成。保留 readable_name 供人工辨认，但真正身份由 run_id 决定。运行状态包括 pending、running、success、partial、blocked、failed；成功生成文件不等于研究已经通过质量门槛。

运行清单至少保存 Git commit、工作区是否有未提交变更及其补丁摘要、依赖锁文件、参数、随机种子、数据清单哈希、股票池版本、因子版本、标签、切分、模型、交易规则和评价版本。

### 15.2 输出产物

```text
runs/<run_id>/
  manifest.json           # 运行身份、版本、状态、证据级别
  resolved_config.yaml    # 展开默认值后的实际配置
  data_manifest.json      # 实际读取的不可变分区与哈希
  split_plan.parquet      # 每个窗口的日期及 fit_asof
  feature_catalog.json    # 实际使用的因子和版本
  models/                 # 模型与预处理器
  predictions.parquet     # 冻结样本外分数
  targets.parquet         # 目标权重/数量
  orders.parquet          # 全部订单与拒单原因
  fills.parquet           # 成交
  positions.parquet       # 持仓与可卖量
  equity.parquet          # 现金、资产、日收益
  metrics.json            # 统一指标
  limitations.json        # 数据与执行限制
  reports/                # 选择生成的图表与摘要
  logs/                   # 可定位到阶段的运行日志
```

研究结果大表存 Parquet，小型配置用 YAML/JSON。报告只保留必要摘要，不自动为每个中间步骤生成长篇 HTML 或 Markdown。最终组合报告可以使用 QuantStats，因子报告可以使用 Alphalens，但都应能追溯到同一 run_id。[R07][R08]

### 15.3 数据冻结不等于复制全部历史

采用不可变分区和内容哈希清单。新实验复用已有分区，无需为每次运行复制整个市场数据；新版本只新增或替换引用。垃圾清理不得删除仍被任何保留实验引用的数据。

需要更换来源、修正公式或调整单位时产生新的数据/特征版本；已有实验不能在同名目录中被覆盖。增量更新、因子缓存和模型缓存分别管理，避免“文件存在”就误认为内容仍适用。

### 15.4 复现标准

在相同依赖、配置和数据版本下，因子、标签、订单和账本应按定义一致；数值模型允许事先声明的小容差。至少保存一条离线复现命令和一个小型固定结果样例。重新运行只记录新的 executed_at，不改变 fit_asof 和原始证据级别。

## 16. 使用入口与日常操作

### 16.1 先命令行，后可选查看页面

第一版提供统一命令入口 `qresearch`；以下命令是待实现的接口规范，不代表目前已存在。参数应支持配置文件和少量显式覆盖，所有覆盖写入 resolved_config。

```bash
qresearch doctor
qresearch data probe --config configs/data_probe.yaml
qresearch data sync --config configs/data_daily.yaml
qresearch data audit --dataset <dataset_id>
qresearch universe build --config configs/universe.yaml
qresearch features build --config configs/features_daily.yaml
qresearch factor evaluate --config configs/factor_eval.yaml
qresearch experiment run --config configs/daily_baseline.yaml
qresearch backtest run --predictions <run_id> --config configs/portfolio.yaml
qresearch compare --runs <run_a> <run_b>
qresearch reproduce --run <run_id> --offline
```

`doctor` 检查依赖、目录权限、配置、数据版本和已启用的引擎规则，不自动下载全市场。`experiment run` 调度已定义阶段，默认复用经过校验的缓存。`backtest run` 读取冻结预测，不重新训练。

### 16.2 Notebook 与可选界面

提供三个短 Notebook：数据质量检查、因子分析、结果对比。Notebook 只调用包内 API，不能成为唯一可运行入口。

后续确需页面时，只做轻量的本地实验列表和结果查看；不引入账户系统。界面不绕过统一配置、不重新计算另一套指标。云服务器部署与多设备同步需要另行决定，本文件不默认用户已经选定部署方式。

### 16.3 出错时应怎样提示

错误信息必须说明阶段、数据集/实验、证券或日期范围、失败原因和下一步可执行操作。例如“5 分钟仅返回近期区间，所请求年份覆盖不足”，而不是仅输出“空 DataFrame”。

结束时显示已完成阶段、有效记录数、警告、被阻断项目和产物位置。区分网络不可用、权限不足、不支持频率、真实无交易记录、解析变化与质量失败，避免统一捕获异常后返回空表。

## 17. 测试、验收与质量门槛

### 17.1 三层测试

单元测试使用合成数据精确验证公式、时点和账本；集成测试使用小型固定快照，覆盖从数据到报告的完整流程；联网接入测试单独标记，不作为离线单元测试运行前提。

真实接入测试必须记录来源和时间。合成数据可用于证明程序正确性，不可用于展示真实策略表现。不同平台/依赖版本需要至少复跑离线闭环和引擎关键规则用例。

### 17.2 必须覆盖的数据与时间用例

| 用例 | 预期结果 |
| --- | --- |
| 相同分区重复下载 | 标准表主键不重复，版本清单可追溯 |
| 下载中断或写入失败 | 原版本可读，进度不越过失败分区 |
| 请求多年分钟数据但仅返回近期 | 标记截断与实际范围，不宣称完整 |
| 历史开盘为零或占位 | 字段无效；不能进入开盘成交或完整 OHLC 特征 |
| 股/手与成交额单位不同 | 标准化后数值一致，保留原始单位 |
| 周末、节假日、午间休市 | 下一事件和分钟分区按真实日历/时段计算 |
| 两个市场相同六位代码 | instrument_id 不冲突 |
| 训练结束但未来标签未成熟 | 该样本不进入拟合 |
| 标签 h=5 且次日进入 | 精确使用 k+1 与 k+6 的端点 |
| 财报后续修订 | 修订公布前查询返回此前可用版本 |
| 修改未来行情 | 过去因子、过去预测不变；相应未来标签可变化 |
| 当天截面排名与历史标准化 | 前者只用当时可见截面，后者只拟合训练集 |
| 当前股票池与历史池不同 | 历史候选使用历史成员，不倒填当前名单 |
| 全量计算与分区计算 | 预热正确，重叠部分值一致 |

### 17.3 必须覆盖的组合与账本用例

| 用例 | 预期结果 |
| --- | --- |
| 收盘后生成信号 | 最早下一允许事件成交，不能同收盘成交 |
| 停牌或不利价格边界 | 按配置不成交，订单原因可见 |
| 原持仓退出候选池 | 产生卖出意图；不可卖时继续保留资产 |
| 当日买入尚不可卖 | 请求被限制，可卖数量与总持仓分离 |
| 开盘跳空导致资金不足 | 缩量或拒单，不产生隐含借款 |
| 同一开盘买卖资金复用 | 符合所选保守资金模型，不依赖虚构处理顺序 |
| 报价单位和零股卖出 | 按适用规则舍入，不任意碎股买入 |
| 分红除息与到账 | 应收和现金转移正确，不重复计收益 |
| 送转拆股 | 数量与价格调整后总资产守恒 |
| 部分成交、撤单和费用 | 费用只按实际规则产生，状态链一致 |
| 数据最后一根和证券中断 | 不自动假设可在最后价清仓 |
| 关键公司行动无法处理 | 正式评价被阻断，不删除不利持仓 |
| 价格不变的纯交易样例 | 资产损失仅为规定费用和滑点 |
| 每日资产勾稽 | 现金、持仓、应收/应付与净值在容差内一致 |

### 17.4 报告与复现用例

改变因子公式必须使缓存失效；修改测试标签不得影响已生成预测；更换选股参数不得触发模型重训；离线重跑不允许隐式请求网络。无成交、全现金、常数因子、少量有效证券、零波动、缺失基准与未关闭交易均有可解释输出。

至少一个小型账本例子由手工独立计算，对照全部现金流和净值。只在两个库之间得到同样结果，不足以代替独立核对。

### 17.5 验收状态

“代码已实现”“测试已通过”“真实数据已验证”“研究证据充分”是四个不同状态。交付清单分别列出，禁止把 mock 测试通过写成数据源长期稳定，也不能把报告生成成功写成策略有效。

## 18. 分阶段开发计划

### 18.1 阶段一：契约、数据探测与引擎验证

建立最小包、配置、日志和测试。确定字段、时间、标签与账本契约。对 BaoStock/AKShare 做小样本真实能力探测，对 PyBroker 做全部关键账本可行性验证。记录真实版本与未支持能力。

交付：项目骨架、数据源能力清单、小型固定数据集、引擎验证测试、首份设计决策。若引擎或来源受阻，明确限定替代方案，不一次性扩大到更多全平台。

通过条件：能区分数据不存在与接口失败；能证明下一事件成交、资金限制、公司行动与冻结持仓处理路径可实现。前置能力未解决时，不开始大规模收益搜索。

### 18.2 阶段二：日频最小闭环

实现日线标准化、历史候选池、约 20—40 列因子、统一标签、时间切分、单因子诊断、Ridge/LightGBM、冻结预测、等权组合与报告。先用合成/固定快照跑通，再对一份真实数据运行。

交付：一键实验、一键复现、模型及样本外分数、订单/成交/持仓/净值、三层报告。通过条件是小型账本正确、时间测试通过、真实来源与限制可见，不是净值必须盈利。

### 18.3 阶段三：完整第一版补全

扩展历史数据更新、审计、股票池覆盖与分红送转数据；加入 5 分钟接入、分钟质量检查和聚合日频特征；完成有限的去重与前向筛选以及开发/留出分离。

交付：日频基础组与增加分钟特征后的成对实验，实际分钟覆盖报告，持续更新入口，缓存和性能记录。即使分钟因子没有改善，也应保留负结果并完成工程能力验收。

### 18.4 阶段四：有证据再扩展

只选择一个确有需求的方向：近期 1 分钟归档、腾讯快照、公式挖掘、仓位优化、查询加速或轻量结果界面。不同时启动多个方向；每项写明问题、增量指标、预算和停止条件。

## 19. 性能、运行、安全与维护

### 19.1 可控性能，而非未经实测的速度承诺

先记录测试机器、CPU、内存、数据规模和依赖，再测读取、因子、训练、回测、报告各阶段耗时与峰值内存。建议默认性能样例为 300 只股票×约 5 年日线，以及 50 只股票×约 1 年 5 分钟数据；实际记录数以日历和覆盖为准。

这是性能测试工作负载，不承诺某台未知机器在几秒完成。需要做到二次运行复用有效缓存、单因子修改只重算相关结果、小股票池实验不加载全市场分钟数据。规模扩大时优先分区和批量读写，再讨论并行或更换计算引擎。

### 19.2 运行与备份

默认本地单进程调度，允许有限进程用于独立计算；数据写入采用单写者/文件锁避免冲突。更新与实验任务不要同时覆盖同一分区。定时更新可由用户配置操作系统任务调用命令，不建设专门调度服务。

备份至少覆盖配置、代码、锁文件、数据清单、不可重建的原始快照和已保留实验；大数据备份由用户指定位置。删除实验或清理数据必须提供 dry-run，不默认批量删除。

### 19.3 安全与外部输入

密钥、Cookie、个人路径放环境变量或被忽略的本地配置，不写入 Git 和报告。下载文件验证类型、大小和摘要；不能直接执行未知镜像中的程序。模型 pickle/joblib 只加载自己生成并确认来源的文件。

公式执行限制算子和资源；没有必要把任意 Python 代码开放成因子接口。首期不保存券商交易凭证、不接真实下单权限。日志应避免泄漏鉴权参数。

### 19.4 维护规则

增加数据源、因子和模型要走统一接口，并补最小测试与示例。升级依赖后重跑离线闭环和账本用例。源代码引用记录上游路径、版本或 commit 及本地改动，不维护难以追踪的整库复制。

## 20. 风险、默认处理与尚需确认事项

### 20.1 主要风险

| 风险 | 对研究的影响 | 默认处理 |
| --- | --- | --- |
| 免费接口历史不完整或变化 | 样本缩短、字段异常、结果不可复现 | 能力探测、字段审计、本地冻结、有限重试 |
| 历史股票池/财报版本缺失 | 幸存者偏差或未来信息 | 使用历史规则池；未知字段降级或不启用 |
| 日线执行无法还原盘口 | 理想成交过于乐观 | 明确近似、保守拒单、成本情景，不宣称精确执行 |
| 回测库缺少关键规则 | 现金与持仓错误 | 前置合成测试；一轮有界替代，不在报告层补账 |
| 尝试次数过多 | 验证区间被反复适应 | 限定预算、保存全部尝试、保留最终留出 |
| 分钟数据接入拖慢项目 | 长期没有可用闭环 | 先日频闭环，再补 5 分钟；不放弃分钟验收目标 |
| 工程范围扩张 | 基础研究被平台建设替代 | 新模块需满足进入条件，禁止默认全装 |

### 20.2 不阻塞启动的待确认项

实际运行机器与内存、拟研究历史年份、最终股票池范围、真实模拟资金、费用配置、是否需要盘中观察，以及 FreeDB 的准确仓库。Agent 可以使用本文默认值和小样本先推进，但应把它们写入待确认清单，不能伪装成用户已确认决定。

真实费用、某市场历史规则、未知公司行动和无有效开盘价等会影响正式账本的事项，不可用默认值掩盖。允许先完成离线工程与探索研究，必须保持正式评价状态准确。

### 20.3 版本与结论边界

本文件依据截至 2026-09-27 可读取的项目官方说明、API 文档及交易所资料形成。它不是逐个项目安装压测报告，也没有证明任一免费来源覆盖多年全部分钟数据。实现时记录真正通过验证的版本，不照搬旧教程的接口、默认费用或历史规则。

项目第一版的最终形态应是：少量稳定依赖、一套数据与时间契约、清晰的研究对象、可核对的回测账本，以及能够复现正负结果的实验目录。不要把“成熟完备”实现成“不断增加框架”。

## 附录 A. 核心数据契约与字段字典

### A.1 通用约定

下表是逻辑表定义，不要求每张表都部署为数据库。可以采用 Parquet 文件、少量 SQLite 元表和 JSON 清单。大表中的长字符串来源信息可引用 manifest 中的 source_id，避免每行重复存储完整元信息。

`timestamp` 必须遵守统一时区策略；`date` 表示交易日期；`version/id` 是可追溯字符串；状态字段采用枚举，不允许同一状态出现多个自由文本写法。每个版本允许增加字段，但改变含义必须升级 schema_version。

### A.2 数据与证券表

| 逻辑表 | 主要字段 | 主键/关键约束 |
| --- | --- | --- |
| instruments | instrument_id、symbol、exchange、board、asset_type、list_date、delist_date、currency | instrument_id 唯一；未知退市日期与未退市状态分开 |
| trading_calendar | exchange、trade_date、is_open、session_id、open_at、close_at | 交易所+日期+时段；包含例外时段 |

| status_history | instrument_id、effective_from/to、is_st、is_suspended、listing_stage、available_at | 同时保留状态生效与可获知时刻 |
| corporate_actions | event_id、instrument_id、type、announced_at、record_date、ex_date、pay_date、share_ratio、cash_per_share、available_at | event_id 唯一；未支持事件不能静默跳过 |

| targets | run_id、decision_at、execute_after、instrument_id、score_rank、target_weight、target_qty、reason | 计划不是成交；不可行约束有解释 |

| backtester.run | 订单/目标、市场事件、规则 | 成交、持仓、现金、净值，一套权威账本 |

上下文至少携带 snapshot_id、decision_at、fit_asof、rule_version 和 evidence_level。不要把时间与版本依赖藏在全局变量或函数内部的“今天”。

## 附录 F. 简明术语

| 术语 | 本项目中的含义 |
| --- | --- |
| 因子 / 特征 | 给定股票和决策时点可计算的数值输入，不默认有效 |
| 横截面 | 同一个决策日期不同股票之间的比较 |
| 样本外预测 | 模型未使用该段未来标签拟合后，对该段生成的预测 |
| PIT / 当时可用 | 历史查询使用当时已发布的版本，而非今天看到的最终修订值 |
| 标签成熟 | 标签依赖的未来价格和事件已经全部可获得 |
| 滚动验证 | 沿时间多次训练并预测后续区间，保留每次历史边界 |
| IC / Rank IC | 当日股票间因子与未来收益的相关性 / 排名相关性 |
| 换手 | 持仓变化或交易额强度，必须注明具体分母和双边/半换手口径 |
| 滑点 | 参考价格与假设实际成交价格之间的差异，不是精确盘口模拟 |
| 数据快照 | 一次实验固定引用的数据分区与版本清单 |
| 设计参考 / 直接依赖 | 前者学习结构并自行实现；后者在项目中实际调用其代码 |
| 探索性结果 | 存在反复选择或资料限制的研究证据，不冒充严格最终留出验证 |
