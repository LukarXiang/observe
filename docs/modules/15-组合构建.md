# 模块：组合构建（portfolio）

## 职责

在逐日循环的**决策阶段**被调用（见 `16-回测账本.md` 的每日顺序），读取当天冻结的预测分数、当天的研究候选名单和账本的**真实持仓与现金**，产出：

1. 调仓日：**目标名单**（下一次调仓前要持有哪些证券）和订单意图；
2. 非调仓日：只产出**补单**（把上一次调仓没完成的部分继续完成）。

订单**不能预先批量生成**：它依赖当时的持仓和现金，而持仓和现金只有账本逐日跑到那一天才知道。
不做：判断能否成交、计算实际成交股数和费用、更新持仓——这些是账本在执行时做的事。借鉴 hikyuu「一个组件只做一件事」，但只拆「定目标名单」「生成订单意图」两块。

2026-10-01 增加基准用的 `construction: universe_equal`，配合 `scores.source: universe`：调仓日为当天全部历史研究候选重设等权目标，不使用 Top-N 名额、排名缓冲与普通换出数。减持股数按决策收盘价和整手计算，买入意图使用目标与当前持仓市值的金额差；非调仓日只重发未完成的原目标意图。最大权重、参与度、现金策略与交易限制继续生效，实际权重未必恰好等权；实现与手算见 `test_benchmarks.py`。

## 输入

| 输入 | 说明 |
| --- | --- |
| `scores` | 当天的预测分数 `{证券: 分数}`，可能不覆盖所有候选（分数缺失） |
| `eligible` | 当天的研究候选（股票池模块输出中 `eligible = True` 的证券） |
| 当前持仓 | 账本在决策时点的持仓（含卖不掉的） |
| 当前净值与现金 | 账本当天收盘后的数值 |
| 上一次调仓的目标名单与每只目标金额 | 非调仓日补单用 |

## 调仓日：定目标名单（按顺序，不可调换）

记目标持股数为 N（默认 20）、排名缓冲为 b（默认 10）、最大换出数为 `max_sell`（默认 5）。排名只在「有分数的研究候选」内进行，分数相同按证券代码字典序（只为可复现）。

1. **强制退出**：已持有、但当天不在研究候选里的证券（例如变成 ST、长期停牌、退市整理），生成卖出意图，原因 `exit_universe`。**不受 `max_sell` 限制，也不计入换出数。**
2. **分数缺失**：已持有、仍在研究候选里、但当天没有分数的证券，**保持不动**，计入保留集合，记原因 `score_missing`。不当作最差分数强卖。
3. **排名缓冲**：其余持仓中排名在前 N+b 名以内的，保留。
4. **普通换出**：剩下的持仓按分数从低到高卖出，原因 `exit_rank`，数量受 `max_sell` 限制：
   - `max_sell = null`：不限；
   - `max_sell = 0`：除强制退出外不做任何普通换出；
   - 正整数 k：最多换出 k 只；因上限没换出的持仓计入保留集合。
5. **新买入**：保留集合 = 第 2、3 步保留的持仓 + 第 4 步因上限没换出的持仓。从「有分数的研究候选、且未持有」的证券中按分数从高到低补足到 N 只，原因 `enter_top`。
6. **目标名单** = 保留集合 + 新买入。强制退出和普通换出的证券不在目标名单里；它们如果卖不掉（跌停、停牌），仍占用资产和现金，下一次调仓时重新走一遍上面的顺序。

**纯 Top-N** 的写法是 `b = 0` 且 `max_sell = null`。

**定金额**：每只新买入证券的目标金额 = 调仓日收盘净值 / N，受单只上限（默认 10%）约束。保留的持仓**不因价格变动再平衡**。候选不足 N 只时，差额留作现金，不放宽规则凑数。

## 非调仓日：补单（`refill_between_rebalance`，默认开启）

目标名单在两次调仓之间保持不变，**不用当天的新分数重新排名**：

- 目标名单之外、仍持有的证券（上次卖出失败的）：每天继续生成卖单，原因沿用上次（`exit_universe` / `exit_rank`）；
- 目标名单之内、尚未持有或持有市值不足目标金额的证券（上次因资金、涨停、停牌、参与度限制没买够的）：
  生成买单，金额 = 目标金额 − 当前持有市值；不足一个买入单位的差额不补，原因 `refill`；
- 已持有且达到目标金额的证券，不做任何操作。

设为 `false` 时，非调仓日不产生任何订单。

## 订单意图

订单只记录**意图**，股数在账本执行时才计算，这样决策日到执行日之间遇到除权也不会算错：

| 方向 | 记录的内容 | 执行时怎么算 |
| --- | --- | --- |
| 卖 | `qty = "all"`（第一版只有整只卖出） | 执行当天的可卖股数（新增的待上市股份不可卖） |
| 买 | `amount`（目标金额，元） | 按成交价和买入单位向下取整；资金不足时，同一事件内按分数从高到低依次买，后面的缩量或放弃，不借钱 |

订单只在下一交易日开盘这一个成交事件有效，没成交的部分在当天撤销；之后是否再下单由上面的补单规则决定。
卖单排在买单之前（资金规则见 `16-回测账本.md`）。

## 输出

- `targets`：`decision_date`、`instrument`、`score`、`score_rank`、`target_amount`、`reason`（`keep_buffer` / `keep_score_missing` / `keep_max_sell` / `enter_top`）；
- `orders`：`order_id`、`decision_date`、`instrument`、`side`、`amount`（买）或 `qty = "all"`（卖）、`reason`；执行结果（状态、成交股数、拒单原因）由账本写回。

## 后期入口

仓位优化（skfolio 等）在等权基线稳定后才引入；优化所需的风险估计只用决策前数据，分数不直接当预期收益用；优化不可行时回退到等权并记录原因。

## 测试要点

- 缓冲为 10 时，第 25 名的持仓不卖，第 31 名的卖出。
- 持仓在候选内但分数缺失：保留；持仓不在候选内：强制退出且不计入换出数。
- `max_sell` 取 `null`、0、k 三种值的换出数量正确。
- 候选只有 12 只时，只买 12 只，其余现金。
- 非调仓日不重新排名：当天分数变化不产生新的换出；上次没买进的目标股票被补买。
- 换选股参数重新跑逐日循环，不触发模型重新训练（只读预测表）。
