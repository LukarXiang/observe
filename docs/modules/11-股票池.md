# 模块：股票池（universe）

## 职责

对每个决策日，给出「允许参与排序的证券」及每只证券被排除的原因。**只用决策时点已知的信息。**

不做：停牌、涨跌停、可卖数量这类成交可行性检查——那是回测账本在下单那一刻做的事。次日停牌的事实不能拿来剔除前一天的候选。

## 输入

| 输入 | 来源 | 用途 |
| --- | --- | --- |
| 证券主数据 `instruments` | 数据层 | 上市日、退市日、板块、证券类型 |
| 日线 `bars_1d` | 数据层（BaoStock 按日期取全市场） | **当天在市证券的来源**：停牌股也有一行（标记为停牌），天然包含后来退市的股票；另有 ST 标记、成交额 |
| 股票池配置 | `configs/*.yaml` 的 `universe` 段 | 过滤规则 |

## 输出：`universe_members` 表

| 字段 | 含义 |
| --- | --- |
| `decision_date` | 决策日（交易日） |
| `instrument` | 证券 |
| `eligible` | 是否进入研究候选 |
| `reason` | 不入选时的原因代码，入选时为空 |
| `universe_version` | 规则配置的指纹（配置内容的哈希前 12 位） |

原因代码是固定枚举：`not_listed`（当天未在市）、`board_off`（板块未启用）、`too_new`（上市交易日不足）、`st`（当天为 ST）、
`suspended_long`（最近 N 个交易日停牌超过阈值）、`illiquid`（过去 N 日平均成交额低于阈值）、`no_data`（当天及回看期缺日线）。

## 规则（第一版的确定值，均可在配置里改）

1. **历史在市证券** = 当天 `bars_1d` 里有记录的股票（含停牌）。实测 2026-09-24 全市场日线 5222 行，与 BaoStock 当天证券清单中的股票数完全相同；2015-07-08 有 1317 只停牌股同样在列。**不用今天的股票列表倒推。** BaoStock 的某日证券清单（`query_all_stock`）只用于审计时交叉核对。
2. **板块**：默认只启用沪深主板（`60xxxx.SH`、`00xxxx.SZ`）。创业板、科创板、北交所在执行规则集里补齐对应历史规则并通过账本测试后才允许开启。
3. **上市天数**：上市满 120 个交易日（按交易日历数，不按自然日）。
4. **ST**：排除当天日线里 ST 标记为是的证券。ST 标记取 BaoStock 日线的 `isST` 字段，它是逐日的历史值，不是今天的状态。
5. **长期停牌**：最近 20 个交易日里停牌超过 10 天的排除。只看决策日及以前的数据。
6. **流动性**：过去 20 个交易日平均成交额低于 2000 万元的排除。
7. 同一决策日的规则全部基于 `decision_date` 当天收盘后已知的数据。

## 对外函数

```python
build_universe(snapshot, cfg, start, end) -> DataFrame   # 生成 universe_members
members(universe_df, date) -> list[str]                   # 某决策日的候选
```

## 与其他模块的边界

- 因子模块只对 `eligible` 的证券做横截面运算（排名、标准化），但时间序列因子对所有在市证券计算，避免候选资格变化导致因子断档。
- 组合模块只从候选里选新买入；**已持仓证券退出候选只产生卖出意图**，能否卖出由账本判断。

## 测试要点

- 用 2015 年某日构造：清单里有 2019 年才退市的 `000418.SZ`，它必须出现在当天的历史在市证券里。
- ST 用逐日标记：同一只证券在 ST 期间被排除、摘帽后恢复；不能因为今天是 ST 就排除它的全部历史。
- 上市天数按交易日计：跨春节长假时不能按自然日提前满足。
- 次日停牌不影响当天候选。

## 已知限制

- BaoStock 按日期取的全市场日线从 1995 年起有数据，早年逐日是否完整由阶段 1 的审计确认（每月抽 2 个交易日与当天证券清单比对）；审计发现缺失的年份，股票池标为受限样本。
- 北交所及其前身（新三板精选层）的代码迁移（`43xxxx`/`83xxxx`/`87xxxx` → `920xxx`）第一版不处理，北交所默认不启用。
