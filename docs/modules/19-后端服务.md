# 模块：后端服务（api / jobs / cli）

## 职责

把研究核心（数据、因子、模型、账本、评价）以两种入口暴露出来：**命令行**和**本机 Web 接口**。两个入口调用同一组函数，
不存在「只有网页能做」或「网页上另算一套指标」的功能。

2026-10-01：新增 `experiment`、`variant`、`factor eval`、`runs list/show/index`、`compare` 命令，以及因子校验 / 评价、实验列表 / 详情 / 比较与 DuckDB 分页产物接口。`experiment`、`backtest_variant`、`factor_eval` 可排队执行，提交前校验配置。前端本轮暂缓；当前接口和使用说明见 `../07-后端研究框架逻辑.md`。

继续开发后，`run` / `research` / `experiment` 支持 `--no-cache`，队列配置对应 `cache: false`；复现自动禁用缓存。实验详情返回 `cache` 和 `benchmark_eval` 报告；`benchmark_daily` 可按模型、成本情景、日期和基准分页查询，等权账本通过 `model=universe_equal` 读取。历史目录索引覆盖全部研究、变体与基准子实验。

2026-10-02：新增 `data index`（直接执行或 `--queue`）、`data index-bars`、任务类型 `data_index` 和 `GET /api/indices/{index}/bars`。任务参数 `start`、`end`、`indices` 在入队前严格校验；指数代码默认 `000300.SH`。下载或审计失败时旧发布状态保留，任务为 `failed`、CLI 退出码 1，完整审计报告在任务 result 中引用。读接口支持快照、日期与分页，和 CLI 调用同一核心函数。具体入库约束见模块 10。

## 分层

```
研究核心（纯 Python 包 observe.*，不认识 HTTP）
   ↑ 调用
任务执行器（observe.jobs：排队、单进程顺序执行、写日志）
   ↑ 提交任务                ↑ 直接调用
Web 接口（FastAPI）        命令行（observe ...）
```

- 研究核心不导入 FastAPI，可以在 Notebook 和测试里单独使用。
- **写数据的任务一律进队列、同一时刻只执行一个**：BaoStock 全机只能有一个会话，数据分区也要求单写者。读取类请求不进队列，直接查。
- 任务在独立子进程里执行，Web 服务本身不被长任务卡住；子进程的输出写 `data/jobs/<job_id>.log`，前端轮询读取。

## 任务表 `data/jobs.sqlite`

`job_id`、`kind`（`data_init` / `data_update` / `data_minute` / `data_audit` / `data_publish` / `snapshot` / `factor_eval` / `run_experiment` / `backtest_variant` / `reproduce` / `gc`）、
`params`（JSON）、`status`（`queued` / `running` / `success` / `partial` / `failed` / `cancelled` / `interrupted`）、`retry_of`、`created_at`、`started_at`、`finished_at`、
`run_id`（若产生了实验）、`log_path`、`error`。

服务启动时把进程已不存在的 `running` 任务改为 `interrupted`；数据任务从已提交进度续跑。网络错误只在任务内部重试 3 次，间隔 2、4、8 秒；整体失败由用户手动重试，新任务通过 `retry_of` 关联原任务。

## Web 接口（第一版）

所有接口前缀 `/api`，返回 JSON；大表分页或按日期范围取。

| 分组 | 接口 | 用途 |
| --- | --- | --- |
| 数据 | `GET /data/coverage` | 各标准表按年份、按板块的覆盖情况（数据中心页的热力图） |
| | `GET /data/audit/issues` | 质量审计发现的问题列表 |
| | `GET /data/snapshots` | 数据快照列表 |
| 证券 | `GET /instruments?q=` | 搜索证券 |
| | `GET /instruments/{id}/bars?freq=1d&start=&end=&price=raw|adj` | K 线 |
| | `GET /instruments/{id}/actions` | 公司行动 |
| 因子 | `GET /factors` | 因子注册表 |
| | `POST /factors/validate` | 校验表达式（语法、白名单、推算回看天数），不计算 |
| | `GET /factors/{name}/evaluation?snapshot=&start=&end=` | 已算好的因子评价结果 |
| 实验 | `GET /runs` / `GET /runs/{id}` | 实验列表、实验概要（首页固定内容 + 三层指标） |
| | `GET /runs/{id}/equity` `/orders` `/fills` `/positions?date=` | 账本明细，支持按日期、证券下钻 |
| | `GET /runs/compare?ids=a,b` | 成对比较 |
| 任务 | `POST /jobs` / `GET /jobs` / `GET /jobs/{id}` / `GET /jobs/{id}/log?offset=` / `POST /jobs/{id}/cancel` | 提交与跟踪任务 |

读取 Parquet 用 DuckDB 直接查询文件，不先整表载入内存。

## 命令行

```
observe doctor                         检查环境、目录、依赖版本、配置、数据快照
observe data init --from 2005-01-01    首次全量建库（日线、日历、证券、公司行动）
observe data update                    每日增量
observe data minute --pool <池> --from --to
observe data audit                     质量审计
observe data snapshot                  冻结一个数据快照
observe factor eval --config <yaml>
observe run --config <yaml>            跑一次完整实验
observe variant <run_id> --config <yaml>   在已有实验上换组合规则回测
observe compare <run_a> <run_b>
observe reproduce <run_id>
observe serve                          启动 Web 服务（默认 http://127.0.0.1:8765，只监听本机）
```

## 运行方式

### 只读诊断与研究预检（2026-10-02）

`observe doctor [--snapshot <id>] [--config <完整实验 YAML>] [--verify-files]` 调用 `observe.doctor.doctor`。显式快照参数覆盖配置中的快照；两者都没有时检查当前发布状态，并提示正式实验应冻结快照。

- 环境：Python、uv 可用性、核心包安装版本与实际导入；配置启用 LightGBM 时进一步检查 Python 包及原生运行库。
- 配置：沿用 `ExperimentConfig`、因子表达式解析、基线因子与分钟股票池约束、日期顺序、交易规则覆盖与核实标记。
- 数据：分区路径、文件存在性、Parquet 表头、清单行数、必需表、日历空值 / 重复 / 自然日缺口、整日缺失的股票日线、请求区间覆盖；读取指定批次的已有审计。
- 切分：沿用现有预热口径及 `dataset.plan_splits`，输出可用决策日、窗口数、测试起止、最终留出起点；分钟研究使用同一截止日适配器。指数检查覆盖预计测试区间与期初锚点。

默认仅扫描元数据和所需日期列，不做全表指纹核验。`--verify-files` 逐分区读取完整数据，核对 Store 内容指纹和分区内主键；报告全部失败分区，一个失败不会提前跳过该表的其他分区。单个分区失败后，其所在表不参与依赖查询。该检查不替代跨分区主键检查或完整质量审计。

历史秒级时间列可能被 Parquet 无损提升到毫秒，而清单仍保留写入前的指纹。只在「毫秒→秒→毫秒逐值相同」且还原后的整表指纹精确等于旧清单时，记录 `representation_adjustments` 警告；不改文件或清单。丢失毫秒信息、数据值变化或仍不匹配均报错。

结果状态 `ok / warning / error`，CLI 对 `ok` 和 `warning` 返回 0，对 `error` 返回 1；每项检查含名称、状态与证据。`warning` 表示已知限制，不能当作正式研究证据。候选、因子、成熟标签、拟合与账本可执行性仍由实际研究流程判断。

API：`GET /api/doctor?snapshot=<id>&verify_files=false`，或 `POST /api/doctor`，请求体 `{snapshot, config, verify_files}`，其中 config 是完整实验配置对象。两者直接调用同一核心函数，不排队；诊断结果以 HTTP 200 返回，调用者检查 JSON 的 `status`。请求结构不合法返回 422。

诊断不联网、不训练、不创建实验、任务、SQLite 或数据目录，不修复日历、不更新审计、不发布数据。服务自身启动时原有队列 / 实验登记初始化仍照常。检查期间状态文件发生变化会提示报告不再代表最新发布状态；不自动切换输入重算。

`observe serve` 一个进程同时提供接口和前端静态页面（前端构建产物放 `web/dist`）。开发前端时 Vite 开发服务器代理 `/api` 到 8765 端口。
只监听 127.0.0.1，不做登录和权限。

## 测试要点

- 接口测试用 FastAPI 的测试客户端和小型固定数据快照，不联网。
- 两个写数据任务同时提交：第二个排队，直到第一个结束才开始。
- 任务子进程异常退出：任务状态为 `failed`，日志保留，Web 服务不受影响。

### 队列生命周期加固（2026-10-02）

同一根目录的所有 worker 共享一个 SQLite 原子运行席位，领取即写 PID，启动事务内交接到子进程。执行锁由子进程持有；`jobs exec` 校验 running 与 PID，完成更新也按状态和 PID 条件写入。每次调度前恢复失去进程的任务；父 worker 退出但子进程存活时不会恢复或再启动任务。异步启动也监控退出码，迟到的监控结果不能覆盖终态。

无需修改表结构。升级前停用旧版 worker；只支持本机目录，PID 复用采用保守等待。`worker --once` 排空可执行队列，忙时返回；中断后需显式 retry，不自动重跑或强杀。命令与测试边界见 `../07-后端研究框架逻辑.md` 的「长任务队列的执行与恢复」。

### 实验完整性入口（2026-10-02）

`runs verify <run> [--shallow]` 与 `GET /api/runs/{rid}/verify?recursive=true` 共用 `integrity.verify_run`。返回 status、summary、runs、references、issues；API 的核验问题以 HTTP 200 的报告承载，编号不存在为 404。此路由位于通用产物表路由之前，不将 verify 解释成表名。CLI 退出码 0 通过、1 错误、2 有警告；只读检查直接执行，不排队。

### 产物表排序与导出（2026-10-02）

`runs table <run> <table>` 提供与 API 等价的分页筛选；`runs export <run> <table> --output <新 CSV>` 导出全部筛选结果。两者共用日期、证券、模型、成本情景、基准与排序参数；`--date` 优先于起止日期。排序新增 `--sort-by` / `--descending`，API 为 `sort_by` / `descending`。

CSV 路由 `GET /api/runs/{rid}/{table}/csv` 返回 UTF-8 附件；每批 4096 行，正常结束及响应关闭释放 DuckDB 连接。CLI 目标独占创建，不覆盖文件。空值、并列排序、空表、筛选错误和格式约定见 `../07-后端研究框架逻辑.md` 的「实验明细排序、查询与 CSV 导出」。

## 财务与规则策略入口（2026-10-03）

CLI、API 与队列共用财务导入/历史查询及规则策略函数，提交前用严格 Pydantic 配置拒绝未知或缺失关键参数。新增任务种类 financial_import、rule_strategy，沿用现有任务锁、日志、取消/失败状态与实验登记；没有额外的研究训练步骤。

| 入口 | 用途 |
| --- | --- |
| `observe data import-financials --annual ... --quarterly ... --controls ... --definitions ... [--queue]` | 三套归档及来源/字典一起审计后发布 |
| `observe data financial-history --snapshot ... --fields ... --instruments ... --decision-time ...` | 默认 strict / financial_quarterly；探索须 mode=exploratory、lag_days；可指定年度来源 |
| `observe strategy catalog --source ...` | 登记源码、候选依赖和重复，生成版本化清单 |
| `observe strategy run --config ... [--queue] [--no-cache]` | 固定规则信号、目标、成本账本和报告 |
| `GET /api/strategies?status=...&limit=...&offset=...` | 分页查询最新来源清单 |
| `GET /api/data/financial-history?snapshot=...&fields=...&instruments=...&decision_time=...` | 同一时点查询；mode / lag_days / table 参数同 CLI |

`observe reproduce` 支持策略父实验。实验原有表查询与 CSV 导出可读取新增 scores、targets、signal_coverage，strategy 父目录的 orders/fills/positions/equity 按 model/scenario 选成本子账本。API/队列真实子进程、校验和三策略集成测试通过；实际命令与编号见[执行记录](../tasks/2026-10-03-财务数据标准化与策略逐批复现-执行计划.md)。
