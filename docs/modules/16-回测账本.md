# 模块：回测账本（ledger）

## 职责与定位

按 A 股规则逐日模拟：执行订单意图 → 检查能否成交 → 成交 → 更新现金、持仓、应收分红 → 估值 → 勾稽。
**全项目只有这一套资金账**，所有组合结果都从它出来。自己实现，不用 PyBroker（理由见 `../02-决策记录.md` 第 1 条）。

账本和组合构建由**同一个逐日循环**协调（`observe/loop.py`）：预测分数可以提前冻结，但订单必须在循环里按当天的真实持仓和现金生成。
订单、成交、持仓、现金流水都是这个循环模拟产生并保存的结果，不假设历史上的计划都成交了。

不做：选股、定目标名单、训练模型、联网取数。

## 输入

| 输入 | 内容 |
| --- | --- |
| 订单意图 | 组合模块产出，见 `15-组合构建.md` |
| 日线（原始价） | 开盘价、前收盘价、停牌标记、成交额 |
| 公司行动 | 现金分红（每股税前金额、除息日、到账日）、送股/转增比例、配股、吸收合并换股比例 |
| 执行规则集 | 见下文「执行规则集」 |
| 账本配置 | 初始资金、滑点、参与度上限、开盘资金口径等 |

## 每个交易日的事件顺序（固定）

1. **盘前**：
   - 公司行动（见下节）；
   - 昨天买入的股份变为可卖（T+1）；
   - 到账日为今天的应收分红转为可用现金；上市可卖日为今天的待上市股份转为可卖。
2. **开盘成交事件**：执行上一决策时点生成的订单，**先卖后买**，同方向按订单顺序（买单按分数从高到低）：
   - 停牌 → 拒单 `suspended`；开盘价缺失或非正 → 拒单 `no_open_price`；
   - 买单开盘价达到涨停价 → 拒单 `limit_up`；卖单开盘价达到跌停价 → 拒单 `limit_down`；
   - 卖单按执行当天的可卖股数成交；可卖为 0 → 拒单 `not_sellable`；
   - 参与度：单笔成交额不超过「决策日之前 20 个交易日平均成交额」的 5%，超出部分不成交（**不用当天成交量**）；
   - 买单股数 = 目标金额 / 成交价，按买入单位向下取整；资金不足按买入单位缩量，仍不足则拒 `cash`；
   - 成交价 = 开盘价 ×（1 ± 滑点），买入加、卖出减，再按最小报价单位取整（买入向上、卖出向下）。
   资金规则由 `open_cash_policy` 决定：

   | 取值 | 含义 | 地位 |
   | --- | --- | --- |
   | `sell_then_buy` | 同一开盘事件内，卖出所得（扣卖出费用）可立即用于随后的买单 | **默认**；A 股卖出资金当日可用于买入 |
   | `preopen_cash_only` | 买单只能用本事件开始前的可用现金 | 保守对照情景 |

   两种都是「日频开盘参考价近似」，不模拟集合竞价的真实撮合与排队，报告中不得称为精确撮合。
3. **记费用**：佣金（一笔订单最低收费一次）、印花税（仅卖出）、过户费；费率按成交日期查执行规则集。
4. **撤单**：没成交的剩余数量当天撤销。之后是否再下单，由组合模块的补单规则决定（`15-组合构建.md`）。
5. **收盘估值**：持仓按收盘价（原始价）估值；停牌持仓用最近有效价（见「停牌期间的公司行动」），标 `stale_price`。**停牌行里数据源填的占位收盘价不用于估值。**
6. **勾稽**：检查恒等式与现金流水（见下文），写入当日净值。
7. **决策**：收盘数据可用后调用组合模块，按当前真实持仓与现金生成下一交易日的订单意图。

## 公司行动

四个日期分开处理：**股权登记日、除权除息日、现金到账日、新增股份上市可卖日（红股上市日）**。

| 日子 | 账本动作 |
| --- | --- |
| 除权除息日（盘前） | 现金分红 = 持股 × 每股税前现金，记为应收分红（到账日, 金额）；送转股按比例增加总股数，新增部分记为**待上市股份，不可卖**；配股按「不参与认购」处理（股数不变） |
| 红股上市日（盘前） | 待上市股份转为可卖 |
| 到账日（盘前） | 应收分红转为可用现金 |

**日期缺失时从严处理**，标 `assumed` 并在报告限制说明中计数：
- 到账日缺失：除息日在 2014-01-01 及以后的按除息日；之前的按除息日后第 10 个交易日（实测 600519 在 2013 年及以前晚 4–10 个自然日；2014 年分界点待阶段 1 用全量数据验证）；
- 红股上市日缺失：按除权除息日后第 1 个交易日（待阶段 1 验证）。

**跨除权的未执行订单**：订单记录的是金额或「全部卖出」，执行日恰逢除权时，买单用除权后开盘价算股数，卖单用除权后的可卖股数，无需额外调整。
涨跌停判断用数据源给出的前收盘价，它在除权日已是除权参考价。

**停牌期间的公司行动**：停牌持仓的估值价 = 最近有效收盘价按除权公式调整后的参考价
`(P − 每股现金 + 配股价 × 每股配股比例) / (1 + 每股送转 + 每股配股比例)`；能取到数据源的除权参考价时优先用它。
这个估值价与是否参与配股无关；不参与配股只意味着股数不变，价值下降如实计入净值。不允许出现股数增加而估值价未调整。

**分红税口径**：按税前现金分红入账，扣交易费用，**不扣**个人股息红利所得税（A 股按持股期限适用不同税率，第一版不跟踪）。
报告首页写明「收益已扣交易费用，未扣个人股息红利所得税」，不得称为个人税后收益。

## 执行规则集（rule profile）

规则分两张表，放在 `configs/rule_profiles/main_board.yaml`：**费用表**按生效日期查（全市场统一）；**交易规则表**按「板块 × 是否 ST × 生效日期」查（涨跌幅、买入单位、报价单位）。两张表各自按日期变化，不必互相复制。每条带 `source` 与 `verified`；账本用到未核实的条目会记录在 `used_unverified`，报告必须披露。**回测覆盖的区间里任何一天查不到规则就报错，不套用默认值。**

| 规则 | 第一版覆盖范围与取值 | 状态 |
| --- | --- | --- |
| 买入单位 | 沪深主板 100 股整数倍；卖出不足 100 股的零股可一次卖出 | 待按交易所规则逐条核实后标「已核实」 |
| 涨跌幅 | 主板 10%；主板 ST 1998-04-22 起 5%，**2026-07-06 起 10%**（沪深两市，真实数据印证，见实测报告第十五节）；新股上市初期另有规则 | 已录入，未核实官方条文 |
| 最小报价单位 | 0.01 元 | 同上 |
| 印花税 | 2005-01-24 双边 0.1%；2007-05-30 双边 0.3%；2008-04-24 双边 0.1%；2008-09-19 起卖方单边 0.1%；2023-08-28 起 0.05%（`stamp_both_sides` 表示双边） | 已录入，未核实 |
| 过户费 | 按成交金额的一定比例，沪深统一后数次下调 | 同上 |
| 佣金 | 研究假设：万分之 2.5，最低 5 元 | 你的实际费率确定后替换；报告里写「研究假设」 |

涨跌停价 = 前收盘价 ×（1 ± 涨跌幅），四舍五入到 0.01 元。前收盘价取数据源给出的「前收盘」（除权日已是除权参考价）。

未启用的板块（创业板、科创板、北交所）规则不进第一版；启用某个板块 = 把它的规则补进规则集 + 通过本文件的测试用例。

## 持仓结构（借鉴 rqalpha 的股票持仓）

```
position: 总股数 qty, 今日买入 today_buy, 待上市股份 pending, 可卖 = qty − today_buy − pending, 加权平均成本, 最近有效价, 是否过期价
dividend_receivable: {到账日: 金额}
cash_events: 每一笔现金变动（买入、卖出、费用、分红到账）
```

## 恒等式与数值精度

每个交易日必须满足：

```
净值 = 可用现金 + 持仓市值 + 应收分红 − 应付费用
```

（日频第一版不存在冻结现金和应付费用，两项恒为 0，字段保留。）
金额用 Python `float` 计算、每笔成交后四舍五入到 0.01 元；恒等式容差 0.01 元。

净值是由现金、市值、应收相加得到的，只检查上面这个等式没有意义（永远成立）。真正的勾稽是**现金流水核对**：
每日现金必须等于「初始资金 + 全部 `cash_events` 之和」，且 `cash_events` 里每一笔都能对应到一笔成交、一笔费用或一笔分红到账。
账本出现负现金、负持仓、卖出超过可卖股数，立即抛错并定位到日期、证券、订单。

## 无法处理的情况（阻断而不是猜）

| 情况 | 正式评价 | 探索模式 |
| --- | --- | --- |
| 持仓遇到吸收合并但换股比例表里没有 | 阻断 | 按最后价格估值继续，标出受影响持仓与日期 |
| 持仓证券退市（退市整理期结束） | 阻断 | 同上 |
| 持仓长期停牌超过 60 个交易日 | 继续，但报告列出 | 同上 |
| 除权除息日在公司行动表里缺失（由复权因子反推发现不一致） | 阻断 | 同上 |
| 回测区间结束 | 不自动清仓，按收盘价估值 | 同左 |

## 输出表

`orders`（补全状态：`filled` / `partially_filled` / `rejected` / `cancelled`，以及 `qty_filled`、`reject_reason`），
`fills`（`fill_id`、`order_id`、`date`、`qty`、`ref_price`、`fill_price`、`commission`、`stamp_tax`、`transfer_fee`），
`positions`（每日每只：`qty`、`qty_sellable`、`close`、`market_value`、`stale_price`），
`cash_events`（非交易现金变动：分红应收、分红到账，带关联的公司行动编号），
`equity`（每日：`cash`、`market_value`、`receivable`、`equity`、`daily_return`、`turnover`）。

## 测试用例（全部用合成数据，手算预期值）

1. 决策日收盘生成信号 → 最早下一交易日开盘成交，不会同日收盘成交。
2. 当日买入的股票当日卖单被拒 `not_sellable`，次日可卖。
3. 停牌拒单；开盘即涨停的买单拒单、开盘即跌停的卖单拒单。
4. 跳空高开导致资金不足：按 100 股缩量；不足 100 股拒单；现金永不为负。
5. 同一开盘时刻卖出 A、买入 B：`sell_then_buy` 下 B 可用卖 A 的回款；`preopen_cash_only` 下不可用。
6. 现金分红：100 股 × 10 元，每股派 1 元，除息后价格 9 元 → 除息日净值 1000 元（900 市值 + 100 应收）；到账日应收转现金，净值不变、不重复计收益。
7. 10 送 10：100 股 × 10 元 → 200 股 × 5 元，净值不变；新增 100 股在红股上市日前不可卖。
8. 配股不参与：股数不变、除权价下跌，净值下降额等于除权价差 × 股数；与复权标签的差异可解释。
9. 最低佣金：成交额 1 万元、费率万分之 2.5 时佣金按最低 5 元收。
10. 价格不变的买入再卖出：净值损失恰好等于双边费用 + 滑点。
11. 持仓证券退市：状态为阻断，持仓不从账本里消失。
12. 区间结束不自动清仓。
13. 印花税跨 2023-08-28：同样的卖单，前一天 0.1%、当天 0.05%。
14. 每日恒等式与现金流水核对在全部用例中成立。
15. 逐日循环：满仓换仓后的现金与持仓轨迹，两种资金规则分别断言；卖出失败影响下一次调仓；非调仓日补单。
16. 送转跨越未执行订单；停牌期间现金分红与送转；停牌占位收盘价不用于估值。
17. 到账日、红股上市日缺失时按从严规则推断并标记。
18. 成本情景：费率加倍后，第二次调仓的订单金额与基础情景不同，且与手算一致。

至少一个用例的全部现金流由人工在表格里独立算出，与账本逐笔比对。
