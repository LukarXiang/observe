# 模块：数据层（data）

## 职责

从免费接口和外部文件取数 → 原样留底 → 标准化 → 审计 → 按时间分区写入 → 冻结快照。研究代码只读快照里的标准表，**不联网**。

不做：计算因子、判断候选、模拟成交。

数据源的实测事实见 `../01-数据源实测报告.md`，分工的取舍见 `../02-决策记录.md` 第 4 条。

## 目录

```
data/
  raw/<上游>/<数据集>/<键>.parquet     原始记录，原样保存（字段全为字符串），只追加
  raw/requests.jsonl                   每次请求一行：来源、上游、接口、参数、开始时间、耗时、状态、行数、错误
  std/<标准表>/<分区>__<指纹8位>.parquet 标准表分区；文件名带内容指纹，内容变了就是新文件
  std/<标准表>/                       标准表分区（发布状态由 data/PUBLISHED.json 统一管理）
  snapshots/<快照编号>.json            快照：各表引用的分区文件与指纹
  coverage/                            覆盖进度；审计提交产物位于 audits/<audit_id>.*
  jobs.sqlite  jobs/                   任务队列与任务日志（见 19-后端服务）
```

## 标准表

所有表的证券代码统一为 `600000.SH` 形式；日期为交易日（`date` 类型）；时间戳为北京时间的时区无关值（全项目只有一个时区，不做时区换算）；
价格单位元，成交量单位**股**，成交额单位元，比例用小数。

| 表 | 分区 | 主键 | 主要字段 | 主源 |
| --- | --- | --- | --- | --- |
| `calendar` | 单文件 | `date` | `is_open` | BaoStock |
| `instruments` | 单文件 | `instrument` | `name`、`kind`（stock/index）、`exchange`、`board`、`list_date`、`delist_date`、`status` | BaoStock 证券基本资料 |
| `bars_1d` | 按年 | `date, instrument` | `open` `high` `low` `close`（原始价）、`preclose`、`volume`、`amount`、`turnover`、`is_trading`、`is_st`、`pe_ttm`、`pb_mrq` | BaoStock 按日期取全市场 |
| `adj_factors` | 单文件 | `instrument, ex_date` | `back_factor`（后复权因子，自该日起生效） | BaoStock |
| `corp_actions` | 单文件 | `instrument, ex_date, kind` | `kind`（cash/bonus/rights/…）、每股现金（税前）、每股送转股数、配股比例与价格、`record_date`、`pay_date`、`bonus_list_date`、`pay_date_quality`（`source`/`assumed`） | 通达信除权除息；到账日和红股上市日由 BaoStock 补 |
| `shares` | 单文件 | `instrument, date` | 总股本、流通股本（变动日） | 通达信除权除息里的股本变化记录 |
| `index_1d` | 单文件 | `date, index` | 开高低收、成交量、成交额 | BaoStock |
| `bars_5m` | 按月 | `bar_end, instrument` | 开高低收、`volume`、`amount`、`source` | BaoStock，2020-01-02 起（决策 16） |
| `share_conversions` | 手工维护的配置文件 | `from_instrument` | `to_instrument`、换股比例、生效日、来源链接 | 公告 |

**存储占用**（实测，见实测报告第十四节）：第一版实际要存的是日线（2005 年起全市场，约 1 GB）和分钟股票池 2020 年起的 5 分钟线（约 1.6 GB），合计约 3 GB。作为参照，25 年全市场的 5 分钟线约 15 GB、1 分钟线约 60 GB。15/30/60 分钟线读取时由 5 分钟线合成，不单独存。
1 分钟数据读进内存约 70 字节一行，全市场一年约 21 GB，只能按月、按证券分批处理。

**停牌行的处理**：BaoStock 在停牌日也返回一行，开高低收都填成前收盘、成交量为 0 或空。标准化时：`is_trading = False`，
开高低收设为缺失，`preclose` 保留（用于估值）。**停牌日的价格不是成交价**，不能被因子当作真实交易、不能被账本当作可成交价。

**后复权价**不单独存表，读取时由 `bars_1d` 的原始价乘以当日生效的 `back_factor` 得到（因子模块的基础字段 `close_adj` 等由此而来）。`adj_coverage` 同时记录 `status`、`verified_from`、`verified_through`、`has_start_basis`、`has_gap`、`confirmed_no_events`、`verified_at`、`source`、`evidence`；只有起始基准可信且日期位于连续验证区间才是 `usable`。空复权表或未知覆盖只返回缺失原因，不把未下载数据当作无公司行动。

## 标准化规则（按来源）

| 来源 | 要点 |
| --- | --- |
| BaoStock | 代码 `sh.600000` → `600000.SH`；成交量已是股；`turn` 是百分数，除以 100；`tradestatus = 0` 为停牌；`isST = 1` 为 ST；5 分钟线的 `time` 形如 `20260924093500000`，取前 12 位为区间结束时刻 |
| 通达信逐笔（按需扩展时使用，第一版只用于抽样核对） | 成交量单位是手，乘 100；时间只到分钟；**合成 5 分钟线时按交易所用不同的边界规则**：上交所按分钟标签直接归入「向下取整到 5 分钟再加 5 分钟」的那根；深交所每个 5 分钟边界分钟里的第一条快照归入上一根（实测不加这条规则收盘价一致率只有 69%，加上后 98%）；9:25 集合竞价并入 9:35；15:00 之后的盘后成交剔除 |
| 新浪 / 腾讯（经 AKShare） | 只用于核对；经 AKShare 取回的成交量两家都已是股（实测与 BaoStock 比值为 1）；新浪不含停牌日和退市股，腾讯含退市股但不含退市前的停牌期 |
| 东方财富 | 成交量为手；请求必须带浏览器请求头且不走代理 |
| 外部导入 | 你提供的文件先转成同样的标准字段，再走同样的审计；与主源重叠的区间逐项比对，一致率达标后才采用 |

## 下载方式与耗时估算（依据实测）

| 任务 | 做法 | 估算 |
| --- | --- | --- |
| 交易日历、证券基本资料 | 各 1 次请求 | 1 分钟内 |
| 日线全量初始化（2005 年起约 5270 个交易日） | BaoStock 按日期逐日取全市场，一天一次请求；按年提交分区 | 约 25 小时（实测每天约 17 秒，服务端负载会波动）；可断点续传 |
| 复权因子 | BaoStock 按证券取全历史（约 5900 只） | 数十分钟 |
| 公司行动与股本 | 通达信除权除息，按证券一次取全历史（约 0.03 秒一只） | 数分钟 |
| 到账日补全 | 只对通达信显示有现金分红的「证券 × 年份」查 BaoStock 分红表 | 2014 年以后缺失按除息日，2014 年以前按除息日后第 10 个交易日，并标 `assumed` |
| 指数日线 | BaoStock 按指数取全历史 | 数分钟 |
| 每日增量 | 收盘后：日历检查 → 当日全市场日线 → 当日复权因子变动 → 有变动的证券重取公司行动 | 几分钟 |
| 5 分钟线（2020 年起） | BaoStock 按证券、按年取（实测一只一年 10–28 秒）；每年只取当年分钟股票池名单内的证券 | 约 15–41 小时，可断点续传 |

**已退市证券**：BaoStock 日线有；通达信分时和逐笔完全没有（实测 000418、600087、002450 在任何年份都为空）。
BaoStock 的 5 分钟线则包含 2020 年以后退市的证券。第一版只用 BaoStock 2020 年起的 5 分钟线，没有这个问题；将来若按需扩展、用通达信合成 2020 年以前的数据，那部分**缺已退市证券**，基于它的研究在报告里标「受限样本：缺退市证券的分钟数据」，除非你提供外部数据补齐。

## 分钟股票池

按年保存名单表 `minute_universe`：`year`、`instrument`、`rank`、`avg_amount`（上一自然年全部交易日原始成交额的算术平均，单位元，停牌日不计入分母）、
`traded_days`（至少 120 天才入选）、`generated_asof`（上一年最后一个交易日收盘后）。每年取前 800 只沪深主板股票。
下载起点 = max(2020-01-02, 入选年初 − 预热天数)，预热天数取分钟特征里最长的滚动窗口（默认 20 个交易日）。
分钟特征按所需时间段判断完整性（见 `12-因子与表达式.md`），不只看全天根数。

## 请求与容错

- **不走系统代理**；每个上游一个会话，带超时（15 秒）；东方财富额外带浏览器请求头。
- **限频**：每个上游设最小请求间隔（BaoStock 0 秒但单会话串行；新浪、东方财富 1 秒；通达信每连接 0 秒、最多 4 个连接分布在不同服务器）。
- **重试**：网络错误最多重试 3 次，间隔 2、4、8 秒；仍失败记入失败清单，任务状态为 `partial`，**不把失败当作「没有数据」**。
- **区分空结果**：接口明确返回 0 行（如停牌、未上市）与请求失败分开记录；「这一天全市场 0 行」一律视为异常。
- **BaoStock 单会话**：全机只允许一个 BaoStock 任务运行（见决策 13）。
- **原子写入**：分区先写临时文件，校验行数与主键唯一后再改名替换，最后写入批次清单；只有提交成功的分区才推进下载进度，审计通过后原子替换 `PUBLISHED.json`。
- 同一分区重复下载，按主键去重后内容相同则指纹不变，不产生新文件。

## 快照

`observe data snapshot` 读取已发布状态，写出 `snapshots/<YYYYMMDD-HHMMSS>.json`：每张表引用的分区文件名、行数、内容指纹、数据最新日期。
实验只引用快照编号。新下载的数据先进入未发布批次，不影响已有快照；审计通过后才更新 `PUBLISHED.json`。一次更新任务产生一个批次清单 `data/batches/<batch_id>.json`，日线、复权因子、公司行动必须在同一批次里审计通过后才发布（原子改写 `data/PUBLISHED.json`），研究永远读不到「日线已更新、复权因子未更新」的中间状态（决策 19）。

**清理**默认 `--dry-run`，显式确认后才删除，且必须保护：当前已发布批次、所有保留的快照、被任何实验或实验变体引用的快照、正在运行的任务固定的输入。

## 质量审计（`observe data audit`）

审计开始时固定 `PUBLISHED.json` 的 `batch_id`，日线、日历和证券资料均从该状态读取，并通过 pin 防止清理删除引用分区。明细 CSV 与元数据 JSON 使用同一个 `audit_id` 原子提交；零问题结果也会落盘。接口按当前批次返回 `not_audited`、`passed`、`problem` 或 `expired`，旧批次的 latest 指针不能覆盖当前批次的有效结果。

每条规则产出「问题清单」，按严重程度分三级：**阻断**（进入快照前必须处理）、**警告**（报告里披露）、**提示**。

| 规则 | 级别 |
| --- | --- |
| 交易日历 BaoStock 与新浪不一致 | 阻断 |
| 某个交易日全市场日线为 0 行，或在市证券数较前一日变化超过 5% 且无上市退市解释 | 阻断 |
| 每月抽 2 个交易日：全市场日线的股票数与 BaoStock 当日证券清单不一致 | 警告（列出多出或缺少的证券） |
| 开高低收违反大小关系（最低 ≤ 开、收 ≤ 最高），或交易日价格非正 | 阻断 |
| 停牌行出现非缺失价格（标准化遗漏） | 阻断 |
| 收盘相对前收盘的涨跌超过当日涨跌幅上限（新股首日等例外除外） | 警告 |
| 复权因子在没有公司行动的日子发生跳变，或有公司行动而复权因子不变 | 警告 |
| 成交额 / 成交量 偏离当日价格区间 | 警告 |
| BaoStock 与新浪日线抽样逐项比对不一致 | 警告（列出明细） |
| BaoStock 已退市证券数与交易所退市清单不一致（实测 337 对 367） | 提示：逐只登记原因（转板、B 股、代码变更、确实缺数等），不预设为缺数 |
| 5 分钟线单日根数不是 48，或 5 分钟成交量合计与日线成交量偏差超过 1% | 警告 |
| 日线标为停牌的日子却有 5 分钟线（实测 600112、600070 出现） | 警告 |
| 到账日为 `assumed` 的现金分红 | 提示（统计数量） |

覆盖表按「表 × 年 × 板块」统计应有证券数、实有证券数、缺失清单，供前端数据中心的热力图使用。
