# 模块：数据层（data）

## 职责

从免费接口和外部文件取数 → 原样留底 → 标准化 → 审计 → 按时间分区写入 → 冻结快照。研究代码只读快照里的标准表，**不联网**。

不做：计算因子、判断候选、模拟成交。

数据源的实测事实见 `../01-数据源实测报告.md`，分工的取舍见 `../02-决策记录.md` 第 4 条。

## 目录

```
data/
  raw/<上游>/<数据集>/<键>.parquet     原始记录，原样保存（字段全为字符串），只追加
  raw/requests.jsonl                   每次请求一行：来源、上游、接口、参数、开始时间、耗时、状态、行数、错误
  std/<标准表>/<分区>__<指纹8位>.parquet 标准表分区；文件名带内容指纹，内容变了就是新文件
  std/<标准表>/                       标准表分区（发布状态由 data/PUBLISHED.json 统一管理）
  snapshots/<快照编号>.json            快照：各表引用的分区文件与指纹
  coverage/                            覆盖进度；审计提交产物位于 audits/<audit_id>.*
  jobs.sqlite  jobs/                   任务队列与任务日志（见 19-后端服务）
```

## 标准表

所有表的证券代码统一为 `600000.SH` 形式；日期为交易日（`date` 类型）；行情时间戳为北京时间的时区无关值；财务可用性时间戳带 Asia/Shanghai 时区，见下文财务查询约定；
价格单位元，成交量单位**股**，成交额单位元，比例用小数。

| 表 | 分区 | 主键 | 主要字段 | 主源 |
| --- | --- | --- | --- | --- |
| `calendar` | 单文件 | `date` | `is_open` | BaoStock |
| `instruments` | 单文件 | `instrument` | `name`、`kind`（stock/index）、`exchange`、`board`、`list_date`、`delist_date`、`status` | BaoStock 证券基本资料 |
| `bars_1d` | 按年 | `date, instrument` | `open` `high` `low` `close`（原始价）、`preclose`、`volume`、`amount`、`turnover`、`is_trading`、`is_st`、`pe_ttm`、`pb_mrq` | BaoStock 按日期取全市场 |
| `adj_factors` | 单文件 | `instrument, ex_date` | `back_factor`（后复权因子，自该日起生效） | BaoStock |
| `corp_actions` | 单文件 | `instrument, ex_date, kind` | `kind`（cash/bonus/rights/…）、每股现金（税前）、每股送转股数、配股比例与价格、`record_date`、`pay_date`、`bonus_list_date`、`pay_date_quality`（`source`/`assumed`） | 通达信除权除息；到账日和红股上市日由 BaoStock 补 |
| `shares` | 单文件 | `instrument, date` | 总股本、流通股本（变动日） | 通达信除权除息里的股本变化记录 |
| `index_1d` | 单文件 | `date, index` | 开高低收、成交量、成交额 | BaoStock |
| `bars_5m` | 按月 | `bar_end, instrument` | 开高低收、`volume`、`amount`、`source` | 外部 1 分钟线合成（`source = external_1m`，决策 20）；BaoStock 2020 年起的 5 分钟线保留为比对与补退市股用（决策 16） |
| `minute_universe` | 单文件 | `year, instrument` | `rank`、`avg_amount`、`traded_days`、`generated_asof` | 由 `bars_1d` 生成 |
| `share_conversions` | 手工维护的配置文件 | `from_instrument` | `to_instrument`、换股比例、生效日、来源链接 | 公告 |

**存储占用**（实测，见实测报告第十四节）：第一版实际要存的是日线（2005 年起全市场，约 1 GB）和分钟股票池 2020 年起的 5 分钟线（约 1.6 GB），合计约 3 GB。作为参照，25 年全市场的 5 分钟线约 15 GB、1 分钟线约 60 GB。15/30/60 分钟线读取时由 5 分钟线合成，不单独存。
1 分钟数据读进内存约 70 字节一行，全市场一年约 21 GB，只能按月、按证券分批处理。

**停牌行的处理**：BaoStock 在停牌日也返回一行，开高低收都填成前收盘、成交量为 0 或空。标准化时：`is_trading = False`，
开高低收设为缺失，`preclose` 保留（用于估值）。**停牌日的价格不是成交价**，不能被因子当作真实交易、不能被账本当作可成交价。

**后复权价**不单独存表，读取时由 `bars_1d` 的原始价乘以当日生效的 `back_factor` 得到（因子模块的基础字段 `close_adj` 等由此而来）。`adj_coverage` 同时记录 `status`、`verified_from`、`verified_through`、`has_start_basis`、`has_gap`、`confirmed_no_events`、`verified_at`、`source`、`evidence`；只有起始基准可信且日期位于连续验证区间才是 `usable`。空复权表或未知覆盖只返回缺失原因，不把未下载数据当作无公司行动。
视图的状态、数值与原因始终一致：`usable` 有值、无原因；`unavailable` 无值、必有原因（`coverage_unknown`、`unknown_gap`、`outside_verified_coverage`、`coverage_not_verified`、`invalid_factor`、`coverage_conflict`）；`estimated` 只在显式 `allow_estimated=True` 时出现，保留候选因子并标明未经覆盖核实。
覆盖完整（有起始基准或确认无事件）且在首个事件之前的日期，因子取初始基准 1。因子必须有限且大于零，事件记录因子缺失或非法时该证券整段不可用；覆盖声明「无事件」而区间内却有事件时报告 `coverage_conflict`。布尔字段明确解析，字符串 `'False'` 是假，无法识别的值报错。

增量更新推进覆盖（单段连续规则）：已有可信起始基准的证券，若原 `verified_through` 到本批首日之间的每个自然日都在交易日历里且都是休市日，并且本批每个交易日的复权查询都完整成功（包括明确确认当日无事件），`verified_through` 推进到本批末日，当日有事件的证券状态为 `complete`。中间日历未覆盖、有未下载的交易日、查询失败或返回未知时都不推进，缺口不会被填平；没有可信基准的证券仍记 `partial`，`partial` 不覆盖可信记录。

## 标准化规则（按来源）

| 来源 | 要点 |
| --- | --- |
| BaoStock | 代码 `sh.600000` → `600000.SH`；成交量已是股；`turn` 是百分数，除以 100；`tradestatus = 0` 为停牌；`isST = 1` 为 ST；5 分钟线的 `time` 形如 `20260924093500000`，取前 12 位为区间结束时刻 |
| 通达信逐笔（按需扩展时使用，第一版只用于抽样核对） | 成交量单位是手，乘 100；时间只到分钟；**合成 5 分钟线时按交易所用不同的边界规则**：上交所按分钟标签直接归入「向下取整到 5 分钟再加 5 分钟」的那根；深交所每个 5 分钟边界分钟里的第一条快照归入上一根（实测不加这条规则收盘价一致率只有 69%，加上后 98%）；9:25 集合竞价并入 9:35；15:00 之后的盘后成交剔除 |
| 新浪 / 腾讯（经 AKShare） | 只用于核对；经 AKShare 取回的成交量两家都已是股（实测与 BaoStock 比值为 1）；新浪不含停牌日和退市股，腾讯含退市股但不含退市前的停牌期 |
| 东方财富 | 成交量为手；请求必须带浏览器请求头且不走代理 |
| 外部导入 | 你提供的文件先转成同样的标准字段，再走同样的审计；与主源重叠的区间逐项比对，一致率达标后才采用。分钟线的做法见下节 |

## 下载方式与耗时估算（依据实测）

| 任务 | 做法 | 估算 |
| --- | --- | --- |
| 交易日历、证券基本资料 | 各 1 次请求 | 1 分钟内 |
| 日线全量初始化（2005 年起约 5270 个交易日） | BaoStock 按日期逐日取全市场，一天一次请求；按年提交分区 | 约 25 小时（实测每天约 17 秒，服务端负载会波动）；可断点续传 |
| 复权因子 | BaoStock 按证券取全历史（约 5900 只） | 数十分钟 |
| 公司行动与股本 | 通达信除权除息，按证券一次取全历史（约 0.03 秒一只） | 数分钟 |
| 到账日补全 | 只对通达信显示有现金分红的「证券 × 年份」查 BaoStock 分红表 | 2014 年以后缺失按除息日，2014 年以前按除息日后第 10 个交易日，并标 `assumed` |
| 指数日线 | BaoStock 按指数取全历史 | 数分钟 |
| 每日增量 | 收盘后：日历检查 → 当日全市场日线 → 当日复权因子变动 → 有变动的证券重取公司行动 | 几分钟 |
| 5 分钟线（2020 年起） | BaoStock 按证券、按年取（实测一只一年 10–28 秒）；每年只取当年分钟股票池名单内的证券 | 约 15–41 小时，可断点续传 |

**已退市证券**：BaoStock 日线有；通达信分时和逐笔完全没有（实测 000418、600087、002450 在任何年份都为空）。
BaoStock 的 5 分钟线则包含 2020 年以后退市的证券。第一版只用 BaoStock 2020 年起的 5 分钟线，没有这个问题；将来若按需扩展、用通达信合成 2020 年以前的数据，那部分**缺已退市证券**，基于它的研究在报告里标「受限样本：缺退市证券的分钟数据」，除非你提供外部数据补齐。

## 分钟股票池

按年保存名单表 `minute_universe`：`year`、`instrument`、`rank`、`avg_amount`（上一自然年全部交易日原始成交额的算术平均，单位元，停牌日不计入分母）、
`traded_days`（至少 120 天才入选）、`generated_asof`（上一年最后一个交易日收盘后）。每年取前 800 只沪深主板股票。
下载起点 = max(2020-01-02, 入选年初 − 预热天数)，预热天数取分钟特征里最长的滚动窗口（默认 20 个交易日）。
分钟特征按所需时间段判断完整性（见 `12-因子与表达式.md`），不只看全天根数。

## 外部分钟线导入（`observe data import-minute`，决策 20）

`--source` 指向 `目录/年/月/YYYYMMDD.zip`（个别是 7z，需 `--sevenzip` 或环境变量 `OBSERVE_7Z`）。默认区间从各年名单的预热起点（首个交易日前 20 个交易日）到日线最后一天，预热期用即将生效的名单。

| 步骤 | 规则 |
| --- | --- |
| 读取 | 只读名单内证券；文件名五种写法与多套一层日期文件夹都识别；同一证券多份取第一份；扩展名是 zip 但内容是 7z 按文件头识别 |
| 解析 | 按表头名取列（列序、有无 `time` 列都会变）；只有表头的空文件剔除 |
| 逐文件校验 | 必须恰好 240 行、无缺失、价格为正、成交量与成交额非负、`open/close` 落在 `low/high` 之间；带时间列的必须与 09:31..11:30、13:01..15:00 一致（20251201–03 的新格式是另一种：时间列是分钟**起点**，上午 119 行、下午 121 行，按时间而不是按位置分到 5 分钟线，经与 BaoStock 累计成交量核对）；任一不过整条剔除 |
| 合成 | 默认每 5 行一组（标签是结束时刻）：开取首、高取最大、低取最小、收取末、量与额求和；结束时刻 09:35 .. 15:00，共 48 根，午休不跨组；价格取两位小数（来源里有单精度噪声） |
| 对账 | 与同日日线：成交量、成交额相对差不超过 1%（另加 500 股 / 5000 元绝对容差）；不过的整条剔除。日线停牌的证券不导入分钟线，有成交记警告；成交量或成交额整日与日线的比值中位数恒为 0.01 时（20251201–03 两者都是）整日乘 100 |
| 审计输出 | `data/minute_audits/<批次>.json` 与 `.issues.csv`；规则：`missing_day`（按证券日记录）、`planned_denominator_incomplete`、`missing_file`、`bars_on_suspended_day`、`unit_rescaled`、`excluded_daily_mismatch`、`excluded_<校验失败原因>`、`refresh_failed_kept_old`、`invalidated_old`，均为警告 |
| 发布 | 批次同时带 `bars_5m`、`minute_universe` 与 `minute_source`，无阻断项即原子发布；已有表的分区不变；内容不变则不产生新批次 |

**重导入保护旧数据**（粒度 = 证券 × 交易日，不再按「本月运行过的日期」整日删除）：

| 集合 | 含义 | 对旧记录 |
| --- | --- | --- |
| 计划处理（planned） | 计划区间内日线有交易的股票池证券日；**覆盖统计的分母**，整日压缩包缺失也在其中 | — |
| 新验证（new_validated） | 本次取得并通过校验、对账的证券日 | 替换旧记录 |
| 刷新失败（failed） | 压缩包或成员文件缺失、无法读取、校验或对账不过 | 沿用旧记录（reused_old），记 `refresh_failed_kept_old`；没有旧记录的记入 missing |
| 被推翻（invalidated） | 日线明确标为停牌，而旧记录里有该证券日的分钟线 | 旧记录移入 `<批次>.quarantine.parquet` 并移出 `bars_5m`，记 `invalidated_old` |
| 已发布（published） | new_validated + reused_old | — |

有刷新失败或计划分母不完整时结果状态为 `published_partial`（任务状态 `partial`），不宣称已完整更新；没有变化但有刷新失败时状态 `no_change`。
**没有任何新验证的证券日时**（所有压缩包缺失、所有文件校验失败）不创建发布批次、不因 `bars_5m` 没有分区而中途退出：已发布数据原样保留，状态 `refresh_failed`（有旧数据，任务状态 `partial`）或 `refresh_failed_no_data`（没有旧数据，任务状态 `failed`、命令退出码 1）；以上三种“没有新批次”的情形都会把逐证券日的问题清单和覆盖统计（planned / new_validated / reused_old / missing / failed / invalidated / published）写进 `data/minute_audits/refresh-<时间>.json` 与 `.issues.csv`，任务日志里的一条错误不能替代它。
**整月旧记录被日线更正推翻**时，`bars_5m` 与 `minute_source` 同步发布该月的空分区，来源表不保留已失效的旧来源；被移出的行在 `<批次>.quarantine.parquet`。
**日历里有该日、日线整日缺失**时无法确定计划处理的证券日：记 `planned_denominator_incomplete`，覆盖统计里 `planned_denominator_complete = false` 并列出这些日期，状态不会是完整的 `published`。`minute_source` 表（按月分区，键 `date, instrument`）记录每个通过校验的证券日的来源：压缩包相对路径与 sha256、成员文件名、CSV 表头、分组方式（`position` / `start_labelled`）、成交量与成交额的单位换算倍数、处理版本（`PROCESSING_VERSION`）；沿用旧记录的证券日保留旧来源，重构之前导入的记录没有来源行。只读核对脚本 `scripts/check_minute_publish.py` 把已发布的 `bars_5m` 与计划分母、历史问题清单及快照逐项对照，不写数据表。

导入不改变日线审计状态的判定：新批次需要重新运行 `observe data audit`，研究才不会带 `data_audit` 限制。已知限制：已退市证券缺分钟数据；最高最低价在 2025-12 之前平均比日线内缩一个最小价位。

## 请求与容错

- **不走系统代理**；每个上游一个会话，带超时（15 秒）；东方财富额外带浏览器请求头。
- **限频**：每个上游设最小请求间隔（BaoStock 0 秒但单会话串行；新浪、东方财富 1 秒；通达信每连接 0 秒、最多 4 个连接分布在不同服务器）。
- **重试**：网络错误最多重试 3 次，间隔 2、4、8 秒；仍失败记入失败清单，任务状态为 `partial`，**不把失败当作「没有数据」**。
- **区分空结果**：接口明确返回 0 行（如停牌、未上市）与请求失败分开记录；「这一天全市场 0 行」一律视为异常。
- **BaoStock 单会话**：全机只允许一个 BaoStock 任务运行（见决策 13）。
- **原子写入**：分区先写临时文件，校验行数与主键唯一后再改名替换，最后写入批次清单；只有提交成功的分区才推进下载进度，审计通过后原子替换 `PUBLISHED.json`。
- 同一分区重复下载，按主键去重后内容相同则指纹不变，不产生新文件。

## 快照

`observe data snapshot` 读取已发布状态，写出 `snapshots/<YYYYMMDD-HHMMSS>.json`：每张表引用的分区文件名、行数、内容指纹、数据最新日期。
实验只引用快照编号。新下载的数据先进入未发布批次，不影响已有快照；审计通过后才更新 `PUBLISHED.json`。一次更新任务产生一个批次清单 `data/batches/<batch_id>.json`，日线、复权因子、公司行动必须在同一批次里审计通过后才发布（原子改写 `data/PUBLISHED.json`），研究永远读不到「日线已更新、复权因子未更新」的中间状态（决策 19）。

**清理**默认 `--dry-run`，显式确认后才删除，且必须保护：当前已发布批次、所有保留的快照、被任何实验或实验变体引用的快照、正在运行的任务固定的输入。

## 质量审计（`observe data audit`）

### 价格指数独立更新（2026-10-02）

`observe data index --start <日期> --end <日期> [--indices 000300.SH,000905.SH] [--queue]` 调用 `data.indices.update_indices`。
以已发布证券主数据确认代码属于指数，要求显式交易所；裸代码不能按股票前缀推测市场。请求区间必须有完整自然日日历及明确开市标记；未知日期或标记不视作休市。首次指数行情开始日前的区间不会自动缩短，需显式选择已有历史的区间。

服务在请求前取得现有 `data-writer` 锁，再通过已有 BaoStock 适配器持会话锁取原始日线。逐行读取结果集，原样响应保存在 `raw/baostock/index_daily/`；标准化日期、代码及数值，不填零、不复权、不静默去重。
每个请求指数都必须覆盖区间内全部交易日；重复主键、错代码、无效 / 非交易日期、缺日、非正或非有限价格、OHLC 顺序错误、负值或非有限量额均阻断整批。指数不套用个股的停牌、涨跌停或 VWAP 审计规则。

全部通过后按主键合并 `index_1d/all`，保留未请求的日期和其他指数，创建批次并原子发布；其他表及已有快照不变。内容相同返回 `unchanged`，不创建新批次。任何一个指数下载或校验失败都返回 `rejected`，旧发布状态不动；CLI 返回 1，队列记为 `failed`。
下载失败、空响应与校验失败同样写 `index_audits/<id>.json` 和 `.issues.csv`：包括请求区间、每个指数的 expected / observed / missing_days、原始文件哈希、输入日历与证券表指纹、基准批次和发布结果。网络与格式问题不会被解释成指数不存在。发布阶段异常记录 `failed` 并抛出，未发布文件保留供排查。

指数审计独立落盘，不冒充股票日线全快照审计。新批次发布后仍需 `observe data audit`，再用 `observe data snapshot` 冻结新研究快照。原实验继续读自己的旧快照。

查询：`observe data index-bars --index 000300.SH [--snapshot <id>] [--start <日期>] [--end <日期>] [--limit 1000] [--offset 0]` 与 `GET /api/indices/000300.SH/bars` 共用 DuckDB 分页函数，返回批次、快照、总行数和数据行。只有显式指定新快照的实验才使用新指数。

### 股票日线审计

2026-10-02 的只读 `doctor --verify-files` 补充检查分区指纹。真实分钟数据暴露出历史时间单位口径：pandas 秒级 timestamp 写 Parquet 后成为毫秒级，值不变但 `hash_pandas_object` 指纹不同。新 `Store.write_partition` 在计算指纹前先把秒级时间列无损提升到毫秒，再保存；重读与重复写入使用同一指纹。既有分区和清单保持原样，doctor 只在逐值无损与旧指纹精确匹配时报告兼容警告。详见模块 19。

审计开始时固定 `PUBLISHED.json` 的 `batch_id`，日线、日历和证券资料均从该状态读取，并通过 pin 防止清理删除引用分区。明细 CSV 与元数据 JSON 使用同一个 `audit_id` 原子提交；零问题结果也会落盘。接口按当前批次返回 `not_audited`、`passed`、`passed_incremental`、`problem`、`expired` 或 `rules_unavailable`，并返回 `scope`、`input_range`、`audit_id`、`audited_at`；只审计了增量区间的通过是 `passed_incremental`，不显示成全快照通过；执行规则加载失败是 `rules_unavailable`，不跳过指纹校验。旧批次的 latest 指针不能覆盖当前批次的有效结果。运行前检查（`observe run`）调用同一判定（`data.audit.audit_status`），快照批次不是全快照审计通过时记为 `data_audit` 限制。

每条规则产出「问题清单」，按严重程度分三级：**阻断**（进入快照前必须处理）、**警告**（报告里披露）、**提示**。

| 规则 | 级别 |
| --- | --- |
| 交易日历 BaoStock 与新浪不一致 | 阻断 |
| 某个交易日全市场日线为 0 行，或在市证券数较前一日变化超过 5% 且无上市退市解释 | 阻断 |
| 每月抽 2 个交易日：全市场日线的股票数与 BaoStock 当日证券清单不一致 | 警告（列出多出或缺少的证券） |
| 开高低收违反大小关系（最低 ≤ 开、收 ≤ 最高），或交易日价格非正 | 阻断 |
| 停牌行出现非缺失价格（标准化遗漏） | 阻断 |
| 收盘相对前收盘的涨跌超过当日涨跌幅上限（新股首日等例外除外） | 警告 |
| 复权因子在没有公司行动的日子发生跳变，或有公司行动而复权因子不变 | 警告 |
| 成交额 / 成交量 偏离当日价格区间 | 警告 |
| BaoStock 与新浪日线抽样逐项比对不一致 | 警告（列出明细） |
| BaoStock 已退市证券数与交易所退市清单不一致（实测 337 对 367） | 提示：逐只登记原因（转板、B 股、代码变更、确实缺数等），不预设为缺数 |
| 5 分钟线单日根数不是 48，或 5 分钟成交量合计与日线成交量偏差超过 1% | 警告 |
| 日线标为停牌的日子却有 5 分钟线（实测 600112、600070 出现） | 警告 |
| 到账日为 `assumed` 的现金分红 | 提示（统计数量） |

覆盖表按「表 × 年 × 板块」统计应有证券数、实有证券数、缺失清单，供前端数据中心的热力图使用。
