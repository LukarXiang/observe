# 模块：实验管理（runs）

## 职责

给每次研究运行一个不可覆盖的编号和目录，记录足以原样重跑的全部信息；按阶段缓存中间结果，改了什么就只重算受影响的阶段。

2026-10-01：完整 `experiment` 实验、`variants/` 预测复用、SQLite 实验登记与三层报告已实现。继续补齐逐因子 / 阶段缓存、同股票池等权账本基准和快照内价格指数评价；实际目录、命令、复现和数据边界见 `../07-后端研究框架逻辑.md`。

## 实验编号与状态

`run_id` = `YYYYMMDD-HHMMSS-<配置指纹前 6 位>-<随机 4 位>`，另存一个人看的 `name`。写入实验登记表依靠主键唯一约束，创建目录要求目录不存在；任一冲突就换随机后缀重试。
状态：`pending`（排队）→ `running` → `success` / `partial`（部分阶段完成）/ `blocked`（账本遇到无法处理的情况）/ `failed`（程序出错）。
「成功」只表示程序跑完，不表示研究结论成立。失败的实验同样保留。

## 阶段与缓存

一次完整实验按顺序经过：股票池 → 因子 → 标签 → 切分 → 训练与预测 → **组合与账本循环** → 评价。组合与账本是同一个逐日循环（决策 17），不是两个先后阶段；它的缓存键包含预测表指纹、组合配置、账本配置、执行规则集与数据快照。
每个阶段的缓存键 = 该阶段配置段的指纹 + 上游阶段产物的指纹 + 该阶段代码模块的版本号。

- 只改选股参数或成本情景：从「组合与账本循环」开始重跑，训练与预测直接复用；
- 只改一个因子公式：只重算这个因子，以及依赖因子的训练与之后的阶段；
- 数据快照变了：全部重跑。

「复用」的判断只看缓存键，不看文件是否存在。

当前实现：`data/cache/stages/<阶段>/<键>/manifest.json` 保存输入与产物哈希；键含实际输入文件哈希、相关代码内容与依赖版本。命中后复制到新实验，逐个键有文件锁和完成后发布机制。损坏条目移入 `data/cache/quarantine/` 保留后重算；异常不发布完整条目。
每次研究 / 回放 / 完整实验保存 `cache.json`，列出各阶段键、`hit` / `miss` / `bypass` / `corrupt_rebuilt`。`cache: false` 或 CLI 的 `--no-cache` 禁用复用；`reproduce` 始终强制重算，仍比较实际数值与冻结输入。不自动清理缓存。

## 目录结构

```
runs/<run_id>/
  manifest.json         编号、名称、状态、证据级别、开始结束时间、Git 提交号、工作区是否有未提交改动、依赖锁文件指纹
  config.yaml           展开默认值后的完整配置
  data_manifest.json    数据快照编号及引用的分区清单
  universe.parquet
  factors.json          实际使用的因子名与版本
  labels.parquet
  split_plan.parquet
  models/               每个窗口的模型文件与说明
  predictions.parquet
  targets.parquet
  orders.parquet
  fills.parquet
  positions.parquet
  cash_events.parquet
  equity.parquet
  metrics.json          三层指标
  limitations.json      数据与执行上的限制、未解决事项
  logs/run.log
```

「回测另一种选股规则」不新建完整实验：在原实验下建子目录 `runs/<run_id>/variants/<variant_id>/`，只放组合、账本、评价三个阶段的产物，
共用父实验的预测。借鉴 qlib 把「信号 → 信号分析 → 组合分析」分开保存的做法。

## 实验登记表

`runs/registry.sqlite` 一张表：`run_id`、`name`、`status`、`config_hash`、`snapshot_id`、`git_commit`、`evidence_level`、`started_at`、`finished_at`、`parent_run_id`。
前端的实验列表只读这张表。

## 复现

`observe reproduce <run_id>`：读取该实验的 `config.yaml` 与 `data_manifest.json`，**禁止联网**，在新目录重跑；
因子、标签、订单、账本应逐值一致，LightGBM 预测在固定线程数下一致，否则列出差异。复现只记录新的运行时间，不改原实验的模拟拟合时点和证据级别。

小型离线回放使用 `observe --root <data> run --snapshot <snapshot_id> [--output <新目录>]`：

- 输出目录必须是新目录：默认 `runs/<时间>-<配置指纹 6 位>-<随机 4 位>`，用独占创建保证不覆盖；显式 `--output` 已存在时报错，不清空、不写入。
- 目录建立后立即写 `status.json`（`running`，逐阶段记录），结束时提交终态 `success` / `success_limited` / `blocked` / `failed`；`manifest.json` 最后写入，失败的目录没有 manifest，不冒充完整实验。
- 市场输入只经过 `observe.execution`：交易日历驱动循环、原始价执行、停牌行保留、公司行动接入账本、参考成交额取决策时点之前的真实历史（预热区间单独读取）。执行区间内整日缺失日线直接 `blocked`。
- 选股是字典序工程基线（`lexicographic_engineering_baseline_v1`），证据级别标明不是预测模型；候选只含启用板块的股票。
- 产物：`config.json`、`data_manifest.json`、`scores.json`（长表 decision_date / instrument / score）、`orders.json`、`fills.json`、`cash_events.json`、`equity.json`、`positions_daily.json`、`receivables.json`、`metrics.json`（评价模块输出）、`trading.json`（换手、费用分项、成交率与拒单原因、现金占比、持仓集中度）、`limitations.json`、`status.json`、`manifest.json`。工程基线不使用标签，标签阶段记为 `not_run`，不生成含义不同的占位文件。

配置：`--config` YAML 与队列参数同构（`snapshot`、`start`、`end`、`initial_cash`、`boards`、`rules`、`portfolio{...}`、`execution{...}`），显式命令行参数 > YAML > 默认值。
`snapshot_id` / `cash` 是别名，与正式名同时出现即报错；未知字段、非法数值（非正现金、NaN、越界比例）报错，不静默丢弃。
`execution.liquidity_override` 只给隔离的合成测试用，设定后运行记为 `success_limited`。
`execution.fee_multiplier` 是成本情景：佣金、印花税、过户费与最低佣金同乘后完整重跑逐日循环（不是固定订单重放），冻结的规则原文不变、倍数记在配置里。

冻结输入：`config.json` 保存展开默认值后的完整配置、快照编号、分数来源（基线名与证据级别）、规则路径 / 原文哈希 / 内容指纹、Git 提交与是否有未提交改动、`uv.lock` 指纹与主要依赖版本；
`rules.yaml` 是实际使用的规则原文；`data_manifest.json` 记录快照全部分区，并对实际读取的分区（交易日历、日线、证券资料、公司行动）记录文件字节哈希。

`observe --root <data> reproduce <run_dir> [--output <新目录>] [--abs-tol 1e-9] [--rel-tol 0]`：

- 先读取并校验源实验（manifest、配置、冻结规则、快照分区字节哈希），全部通过后才创建输出目录；输出等于源目录或落在源目录内部（按解析后的真实路径判断）直接拒绝，源目录只读。
- 使用冻结的 `rules.yaml`，不读工作区当前规则；冻结规则被改动、快照不存在或分区内容与记录不一致时拒绝（`ReproduceRefused`，退出码 1），不称作原实验复现。
- 代码提交、依赖锁文件或依赖版本不同：照常重跑比较，在 `comparison.json` 的 `code_drift` 与结果中列出差异。
- 逐表比较核心产物：分数、订单、成交、现金流水、逐日净值（含应收分红）、逐日持仓、应收分红明细、指标、限制，以及状态中的阻断原因、假设、问题与摘要；按稳定主键对齐，数值按配置的容差比较，差异列出表名、主键（日期、证券）、字段、期望值与实际值。源目录中被改动过的文件另列在 `source_integrity`。
- 不一致时重跑目录的状态为 `mismatch`（`execution_status` 保留重跑本身的执行状态），函数返回、队列任务状态相同，命令退出码 2。

### 研究流水线与样本外预测

`observe --root <data> research --config <yaml> [--snapshot <id>] [--output <新目录>]`（队列任务种类 `research`）：固定快照 → 股票池（`universe.build_universe`）→ 因子（`configs/factor_sets/daily_basic_v1.yaml`，方向与经济含义先验登记）→ 标签（`labels.build_labels`，`adj_open_to_open_h`）→ 切分（`dataset.plan_splits`，最后 `holdout` 个交易日为最终留出，不生成预测）→ 每个窗口：训练窗内秩相关去重、`select` 样本拟合候选并在验证窗按秩 IC 选 Ridge 的 alpha，再用训练 + 验证窗已成熟样本重拟合，预测测试窗 → 因子与模型评价。

- 模型：`single_factor`、`equal_blend` 两个基线与 `ridge`，同窗口同样本比较；模型说明（特征与顺序、系数、训练窗、拟合时点、重拟合方式、被去重的因子）存 `models/split<NN>_<model>.json`，特征名或顺序不一致时预测报错。
- 产物：`universe.parquet`、`factors.parquet`（研究候选行的原始因子值）、`labels.parquet`、`split_plan.parquet`、`predictions.parquet`（`model_id`、`decision_date`、`instrument`、`score`、`split_id`、`fit_asof`、`evidence_level = development_oos`；`minute_pool` 时为 `exploratory`）、`model_eval.json`（逐窗口与汇总的测试窗秩 IC、前 N 名平均标签、Ridge 对两个基线的窗口胜负、全部参数的验证结果）、`factor_eval.json`（开发区间逐因子秩 IC、方向调整后的 IC、覆盖率、按年）、冻结的 `factor_set.yaml`。
- 研究区间从交易日历第 max(上市天数门槛, 最长因子回看 + 1, 流动性窗口, 停牌窗口) 个交易日开始；执行区间内整日缺日线、历史不足一个完整窗口时 `blocked`。候选行复权价不可用的比例记为限制。
- 回放使用预测：`run` 配置 `scores: {source: predictions, run: <研究实验目录>, model: ridge}`，研究候选取该实验的 `universe.parquet`，执行区间默认等于该模型预测的决策日范围；预测表与股票池的文件哈希写进 `config.json`，复现时不一致即拒绝。
身份检查（不满足即拒绝）：研究实验的快照必须与回放快照一致，确需用新快照评价旧预测须显式设 `scores.allow_cross_snapshot`，此时记为对照情景（限制里写明双方快照）；所选模型必须存在；预测必须落在该实验的研究候选上；`fit_asof` 必须早于决策日；请求的起止不得超出该模型预测的定义范围。
- `reproduce` 对研究实验同样适用：校验冻结的因子集与快照后重跑，按主键逐表比较股票池、因子、标签、切分、预测与评价。

### 成对对照实验（阶段 4）

`observe --root <data> paired --config configs/research/paired_intraday_v1.yaml [--snapshot <id>] [--output <新目录>]`（队列任务种类 `paired`）：
在同一快照上依次运行两次研究实验（`minute_pool: true`，只有因子集不同：基础因子集 / 基础 + 分钟因子集），核对两侧 `universe`、`labels`、`split_plan` 逐值相同，
再让两侧的预测各自走同一个回放入口做账本回测（`backtest_models`，默认 Ridge 与等权合成），最后写成对比较。
- 两侧和每个回测都是普通实验目录（与成对目录同级），成对目录 `runs/<id>-paired-<后缀>/` 只放：`config.json`、冻结的 `base_factor_set.yaml` / `extended_factor_set.yaml`、`subruns.json`（各子实验的编号与目录）、`paired_eval.json`（设计口径、模型层与组合层的成对差值及区间、新增因子的开发区间评价、Ridge 使用分钟因子的情况、分钟覆盖）、`limitations.json`、`manifest.json`；
- 分钟股票池研究（`minute_pool`）的实验多产出 `intraday.parquet`（研究候选行 × 分钟特征）与 `intraday_coverage.json`（按年、按证券的覆盖与缺失原因）；用到的 `bars_5m` 分区与 `minute_universe` 按文件哈希写进 `data_manifest.json`；证据级别为 `exploratory`，限制里恒有 `minute_sample_restricted`；
- `reproduce` 对成对目录：逐个复现两侧实验与全部回测（各自逐表比较），再用源目录已保存的产物重算 `paired_eval.json`，逐叶与源文件比较；
- 状态与退出码同上；任一侧被阻断（如快照没有 `bars_5m`）则成对实验 `blocked`。

### 只读重新评价（`observe reevaluate`）

`observe --root <data> reevaluate --source main=<成对目录> [--source sensitivity=<成对目录>] [--output <新目录>]`：评价口径修正后，只读复用已有成对实验里保存的预测、标签、因子、股票池、切分与净值重新评价，不重新训练、不重新下载。先按 manifest 校验源目录与其子实验（不一致即拒绝），结果写到**新的实验目录**（kind = `reeval`），`config.json` 记录各实验的编号与关键产物哈希；源目录一个字节都不改。
产物：`reeval.json`（旧新指标对照及原因、成对预测检查、前 N 名覆盖、开发区间因子评价的留出边界归因、选参重放与每个拟合阶段的正则强度记录、共同测试日期比较、组合状态与诊断前缀）、`paired_eval_new_<标签>.json`、`topn_daily.parquet`。选参重放只重跑选参阶段并与保存的验证秩 IC 逐项对照，用来证明修正没有改变训练选择；`attribution_check` 逐个回测核对持仓归因的截止日（旧算法用 `positions_daily` 最大日期，新算法用净值日历）是否相同，并列出与账户净值勾稽的残差各由什么构成；组合被账本阻断时完整计划区间的组合指标保持不可用，阻断前的共同区间只作 `diagnostic_prefix`，并保存计划区间、可评价区间、截断原因与被排除天数。

### 成对实验诊断（`observe diagnose-minute`）

`observe --root <data> diagnose-minute --source <成对目录> [--source-check <核验文件>] [--output <新目录>]`：只读，写新目录（kind = `diagnostic`，证据级别探索），产物 `diagnostics.json`。内容：缺失模式（从未有分钟数据的候选、与退市的关系、缺失行的标签画像、缺失证券在两侧前 N 名名单里的席位与标签、缺失标记的秩 IC 探针）；打分变化的分解（用保存的模型系数重算：`B` 加分钟侧、`b` 同系数分钟因子置 0、`A` 基础侧，`b − A` 为拟合扰动、`B − b` 为分钟因子数值，另给剔除缺失证券的完整覆盖子样本作受限诊断）；集中持仓贡献（按证券的盈亏、共同 / 独有持仓、缺失证券的贡献、前 5 名占比，阻断的运行只算到阻断日之前）。按证券的盈亏归因（`attribute_run`）：截止日来自净值日历（最后一个早于阻断日的净值日，双方取共同截止日），不是最后一条有持仓的记录；截止日无持仓明细而净值市值大于 0 时报数据不足，不猜；与账户净值勾稽——已分配（每只证券的买卖费用现金流 + 截止日持仓市值）、已识别未分配（分红入账、应收、账户市值与持仓明细之差、其他现金项）、残差；旧产物的分红现金流水不带证券，整笔计入未分配，不按权重摊平，此时贡献比例标为部分归因。
研究选参：全部 Ridge 候选的验证秩 IC 都不可定义时该窗口阻断（`selection_undefined`），并记录每个候选的有效验证日数、有效证券数与不可定义原因，不用第一个 alpha 冒充验证窗选出的。
`scripts/check_missing_minute_source.py` 只做少量证券的来源抽查（压缩包成员与 BaoStock 5 分钟线），不补数。

状态（文件、函数返回值、命令退出码、队列任务同一定义）：`success`（0）、`success_limited`（0）、`blocked`（3）、`mismatch`（2）、`failed`（异常，1）。有限制的阻断仍是 `blocked`。

## 清理

`observe gc --dry-run` 列出未被任何保留实验引用的数据分区和缓存；去掉 `--dry-run` 才真正删除。实验目录本身只有手动指定才删除。

## 测试要点

- 改选股参数不触发重新训练（检查训练阶段未执行）。
- 改一个因子公式，只有该因子及其下游阶段重算。
- 离线复现时任何网络访问都会让测试失败。
- 同一配置运行两次得到两个不同的 `run_id`，互不覆盖。
