# 模块：实验管理（runs）

## 职责

给每次研究运行一个不可覆盖的编号和目录，记录足以原样重跑的全部信息；按阶段缓存中间结果，改了什么就只重算受影响的阶段。

## 实验编号与状态

`run_id` = `YYYYMMDD-HHMMSS-<配置指纹前 6 位>-<随机 4 位>`，另存一个人看的 `name`。写入实验登记表依靠主键唯一约束，创建目录要求目录不存在；任一冲突就换随机后缀重试。
状态：`pending`（排队）→ `running` → `success` / `partial`（部分阶段完成）/ `blocked`（账本遇到无法处理的情况）/ `failed`（程序出错）。
「成功」只表示程序跑完，不表示研究结论成立。失败的实验同样保留。

## 阶段与缓存

一次完整实验按顺序经过：股票池 → 因子 → 标签 → 切分 → 训练与预测 → **组合与账本循环** → 评价。组合与账本是同一个逐日循环（决策 17），不是两个先后阶段；它的缓存键包含预测表指纹、组合配置、账本配置、执行规则集与数据快照。
每个阶段的缓存键 = 该阶段配置段的指纹 + 上游阶段产物的指纹 + 该阶段代码模块的版本号。

- 只改选股参数或成本情景：从「组合与账本循环」开始重跑，训练与预测直接复用；
- 只改一个因子公式：只重算这个因子，以及依赖因子的训练与之后的阶段；
- 数据快照变了：全部重跑。

「复用」的判断只看缓存键，不看文件是否存在。

## 目录结构

```
runs/<run_id>/
  manifest.json         编号、名称、状态、证据级别、开始结束时间、Git 提交号、工作区是否有未提交改动、依赖锁文件指纹
  config.yaml           展开默认值后的完整配置
  data_manifest.json    数据快照编号及引用的分区清单
  universe.parquet
  factors.json          实际使用的因子名与版本
  labels.parquet
  split_plan.parquet
  models/               每个窗口的模型文件与说明
  predictions.parquet
  targets.parquet
  orders.parquet
  fills.parquet
  positions.parquet
  cash_events.parquet
  equity.parquet
  metrics.json          三层指标
  limitations.json      数据与执行上的限制、未解决事项
  logs/run.log
```

「回测另一种选股规则」不新建完整实验：在原实验下建子目录 `runs/<run_id>/variants/<variant_id>/`，只放组合、账本、评价三个阶段的产物，
共用父实验的预测。借鉴 qlib 把「信号 → 信号分析 → 组合分析」分开保存的做法。

## 实验登记表

`runs/registry.sqlite` 一张表：`run_id`、`name`、`status`、`config_hash`、`snapshot_id`、`git_commit`、`evidence_level`、`started_at`、`finished_at`、`parent_run_id`。
前端的实验列表只读这张表。

## 复现

`observe reproduce <run_id>`：读取该实验的 `config.yaml` 与 `data_manifest.json`，**禁止联网**，在新目录重跑；
因子、标签、订单、账本应逐值一致，LightGBM 预测在固定线程数下一致，否则列出差异。复现只记录新的运行时间，不改原实验的模拟拟合时点和证据级别。

小型离线回放使用 `observe --root <data> run --snapshot <snapshot_id> [--output <新目录>]`：

- 输出目录必须是新目录：默认 `runs/<时间>-<配置指纹 6 位>-<随机 4 位>`，用独占创建保证不覆盖；显式 `--output` 已存在时报错，不清空、不写入。
- 目录建立后立即写 `status.json`（`running`，逐阶段记录），结束时提交终态 `success` / `success_limited` / `blocked` / `failed`；`manifest.json` 最后写入，失败的目录没有 manifest，不冒充完整实验。
- 市场输入只经过 `observe.execution`：交易日历驱动循环、原始价执行、停牌行保留、公司行动接入账本、参考成交额取决策时点之前的真实历史（预热区间单独读取）。执行区间内整日缺失日线直接 `blocked`。
- 选股是字典序工程基线（`lexicographic_engineering_baseline_v1`），证据级别标明不是预测模型；候选只含启用板块的股票。
- 产物：`config.json`、`data_manifest.json`、`scores.json`（长表 decision_date / instrument / score）、`orders.json`、`fills.json`、`cash_events.json`、`equity.json`、`positions_daily.json`、`receivables.json`、`metrics.json`（评价模块输出）、`limitations.json`、`status.json`、`manifest.json`。工程基线不使用标签，标签阶段记为 `not_run`，不生成含义不同的占位文件。

`observe --root <data> reproduce <run_dir> [--output <新目录>]` 先读取并校验源实验，再在新目录重跑；输出等于源目录或落在源目录内部（按解析后的真实路径判断）直接拒绝，源目录只读。

## 清理

`observe gc --dry-run` 列出未被任何保留实验引用的数据分区和缓存；去掉 `--dry-run` 才真正删除。实验目录本身只有手动指定才删除。

## 测试要点

- 改选股参数不触发重新训练（检查训练阶段未执行）。
- 改一个因子公式，只有该因子及其下游阶段重算。
- 离线复现时任何网络访问都会让测试失败。
- 同一配置运行两次得到两个不同的 `run_id`，互不覆盖。
