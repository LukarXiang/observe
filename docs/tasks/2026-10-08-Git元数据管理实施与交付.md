## 后续操作

每批先归档原实验和验收，再更新`configs/research_metadata.json`中已验收检查点、任务和阻断。直接使用文档指定的平台解释器执行：

```bash
~/envs/quant/.venv/bin/python scripts/export_research_metadata.py export
~/envs/quant/.venv/bin/python scripts/export_research_metadata.py verify
```

换机仅阅读时，先核验元数据，不运行Store初始化。要复现实验时，先取得主包和审计补充包，核对各receipt包SHA，在新目录检查tar路径并恢复两包，再分别用`prepare_handoff.py verify`核对文件/代码，重建`observe --root data runs index`，最后`observe --root data reproduce <run_id>`。冻结JSON的旧绝对路径不改写。

网络恢复后由可写检出正常fetch并检查master关系，再正常push，禁止force。若远端已前进，先在独立分支保留本提交，按实际差异合并；原工作区有未提交内容时不重置。Git bundle仅迁移Git提交历史，研究数据包另行迁移。
