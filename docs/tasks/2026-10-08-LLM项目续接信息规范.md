# 2026-10-08 LLM项目续接信息规范

本规范配套[Git追踪与跨机数据管理计划](2026-10-08-Git追踪与跨机数据管理计划.md)。它定义拟交付的阅读结构和验收条件，尚未实现元数据导出、入口改造或Git发布。目标是让另一个LLM只读取Git文件，就能准确理解整个项目的目标、已有实现、研究结论、数据限制、执行计划和需要用户决定的事项，并提出有证据支持的建议。

## 统一入口与阅读顺序

复用现有四个入口，动态状态集中到拟新增的metadata索引及其生成页面。

| 文件 | 职责 | 阅读触发条件 |
| --- | --- | --- |
| 根`README.md` | 项目目的、当前状态页、代码/数据管理入口 | 首次了解项目；不手写容易过期的完成数量 |
| 根`AGENTS.md` | 执行规范、环境规则、保护边界和按任务阅读的链接 | 开始操作仓库；保留既有约束，更新“data整体不在Git”的过期说明 |
| 根`CONTEXT.md` | 证券、时间、数据、策略、账本和证据的领域术语 | 对名词或口径有疑问；不作为动态任务日志 |
| `docs/README.md` | 按主题查找需求、架构、功能、数据、研究和历史任务 | 需要理解某模块或历史原因；进入对应章节而不是读完所有文档 |
| 拟新增`docs/10-项目状态与续接.md` | 当前全项目状态、主要结论、阻断、已确认决策和优先下一步 | 研究建议、阶段汇报或开始续接；由metadata生成 |
| 拟新增`data/metadata/index.json` | 权威动态状态、各对象索引及证据引用 | 需要核对计数、版本、对象关系或验证范围 |

仅分析项目时，先读README、状态页及相关metadata，按结论引用追读来源/实验/模块。准备执行时，再读AGENTS及对应环境、执行计划与任务验收条件。根入口不要求每次载入全部历史任务日志。

旧融合记录、批次任务文档和验收凭据保留当时状态，不能为统一入口改写历史。状态页明确注明对应检查点，日期更晚的文件也可能只是进行中记录。当前README仍写5个规则策略，实施时修正；原文留在Git历史。

## 必须保存的全项目状态

`data/metadata/index.json`为单一动态状态入口，至少包含以下内容；大列表通过相对路径与SHA引用，避免将所有数据重复塞入一个JSON。

| 主题 | 必要信息 | 当前需要准确表达的事实 |
| --- | --- | --- |
| 总目标 | 任务范围、状态、完成条件和用户边界 | 继续695来源研究、功能开发及数据允许的复现；全库尚未完成 |
| 工作阶段 | 最近正式验收、进行中步骤、计划版本、下一步任务ID | 第63批已验收211份人工审查；第64批新增2份、组件及禁网匹配完成但正式终审待做 |
| 策略进度 | 全登记/人工审查/目录状态/真实回测/复现/完整原策略的独立计数 | 695登记、213审查、12本机回测来源、67父运行；14代表配置不等于14来源；完整原策略0 |
| 数据状态 | 来源、导入/发布/快照、表与范围、缺口、严格可用性 | 财务与控制变量共575,091归档行；严格历史财务可用0；股本/PCF/名称等未齐 |
| 平台能力 | 代码位置、已验收功能、实际支持的资产/频率/结算及缺项 | 复用唯一Book；指标可计算不等于对应资产可撮合或完整结算 |
| 研究结论 | 财务、量价、模型、分钟成对、策略与组件研究分别汇总 | 不把策略批次当成整个项目；分钟研究及其他已存在成果也需按原凭据纳入 |
| 环境与验证 | 根锁指纹、验证平台/解释器、实际包版本、测试/审查及覆盖 | WSL现有外部环境；安装与根锁的已知差异继续记录，不仅列“使用uv” |
| Git/数据发布 | 验证时base commit、dirty标记、实现文件SHA、元数据覆盖范围、包状态 | 当前有大量未提交变更；计划、已实现、已验收、已提交与已同步分别登记 |

Git当前checkout提交号由阅读者查看仓库获取；同一提交内不要求文件记录自身提交SHA。历史实验保留验证时base commit、dirty及实现文件SHA，新导出登记自身输入和已测试实现指纹。不能把后来提交号回填旧实验，或用代码已上传推断旧回测由当前代码产生。

## 对象关联与证据

每个可分析结论都应沿稳定ID找到以下对象：

    项目目标 -> 任务 -> 来源strategy_id -> implementation/变体
                   |                         |
                 决策                    配置/代码/测试
                                             |
                          snapshot -> run_id -> scenario
                                             |
                            结果 + 基准 + 限制 + 证据
                                             |
                                    阻断与下一步任务

来源记录包含规则、参数、时点、股票池、数据依赖、原文SHA、人工审查状态和下一步。未人工审查的来源只呈现静态候选，不填入“已确认规则”。重要原文表达式或函数可在人工规则记录中保留短引用及行号、来源SHA；全文继续位于repo/和来源包，新LLM缺全文时明确其判断范围。

每个结论保存：结论ID、对象ID、结论文本、性质（事实/推断/提议）、适用范围、输入/配置/实现指纹、验收状态、相对证据路径及SHA、已知限制、被哪条后续结论替代。原始凭据在Git时可直接读取；只有摘要/引用在Git时，标为`summary_only`，原始载荷缺失时标为`payload_missing`，不把摘要SHA当成全链核验。

SHA证明对象身份，不能证明金融口径正确、平台等价或策略有效。接口A/B共用同一C指标内核只能记为接口一致，不标为独立算法验证。研究组件、合成诊断、真实模型拟合和真实交易账本分别记录，不以统称“实验通过”掩盖范围。

## 支持分析建议的必要数据

Git应保存的是“足以理解和检查论据”的结构化信息；逐日大表和完整复现输入继续由包提供。

| 类别 | Git中的必要内容 | 分析能力及边界 |
| --- | --- | --- |
| 已有策略 | 原参数/规则、修正差异、股票池/时点、成本/执行约束、各配置及代码位置 | 可检查规则忠实度及实现风险；缺原文时不能宣称逐行原平台等价 |
| 实验收益 | 三成本、累计/年化/回撤/波动/夏普、分年、相同区间的基准及是否含分红 | 可发现近期恶化和成本敏感性；不同区间、仓位或基准不能直接排名 |
| 交易行为 | 初始资金、平均现金、仓位集中度、换手、订单/成交/拒单/部分成交及公司行动假设 | 能识别复星100万元低回撤与99.44%平均现金的关系 |
| 失败与无效 | blocked原因、数值验收失败、被替代关系、复现差异、涉及证券/日期与证据 | 防止重复踩坑、只挑正收益、把BP阻断净值当作有效回测 |
| 财务 | 字段字典、单位/来源组、映射、公告及版本证据、可用率/未匹配/冲突、严格与探索区别 | 可评估数据需求与前视风险；年度控制变量不冒充每日估值 |
| 数据覆盖 | 表/资产/频率、证券和日期范围、缺失/停牌区分、输入是否在本机/已打包 | 可以规划补数优先级；目录声称的覆盖与载荷实际存在分别核验 |
| 功能 | 能力清单、函数/模块路径、资产限制、相关测试及已执行验证 | 可以提出开发建议并复用本地模块；已有5分钟特征不等于分钟撮合 |
| 代表案例 | 少量真实手算与明确合成边界案例，输入值、单位、日期、预期/实际、来源行及SHA | 可检查费用/时间/指标边界；少量案例不能证明全区间表现 |

首批代表案例复用已有财务跨期/公告门禁、费用手算、动态锚定、国航/复星浮点边界、公司行动转换、RSI/EMA缺失窗口等已验收记录。未取得既有案例原件就登记缺失，不重造一个“相同案例”冒充原证据。单个案例只导出支撑该问题的小窗口和必要字段，遵守管理计划的容量阈值。

## 决策、批准与待回复事项

`data/metadata/decisions/`记录决策ID、来源/变体、具体问题、方案、选择理由、经济规则差异、批准状态、依据摘录/档案、适用范围及替代关系。先审查已有批准文件和来源规则记录，再补齐摘要；只保存必要决策内容，不要求上传全部聊天记录。

已确认的布林、动态锚定配对、SVM形状修正、RSI异常修正、66号兼容修正、国航/复星稳定均值及三进兵TA-Lib方案持续有效。原始档中可定位的批准证据按SHA引用；只从会话确认但没有独立档案的，明确记为`conversation_confirmed`及摘录，不伪造原凭据文件。尚待回复的广汽2020/12、七股低波2022/24继续pending。历史BP清算探索问题也应逐项查证现有批准/结算档，不从数据接口失败或另一变体批准推断其已获批。

新LLM提出的建议记为proposal，用户确认后新增decision关联，原批准记录不覆盖。需要改变经济规则的建议不能直接改冻结实验；已有授权范围内的常规实现和核验无需重复确认。

## 任务和阻断记录

`data/metadata/tasks/`记录任务ID、目标、当前状态、输入依赖、具体下一操作、验收条件、已完成证据、尚缺验证、重要决策依赖和优先级。`blockers.json`记录阻断ID、缺少何物、影响哪些任务/策略、已做尝试、失败类型和解除标准。

任务状态使用planned/in_progress/blocked/completed；验收状态另分pending/passed/failed/not_applicable。某批研究completed可以对应原策略交易blocked，两者并存；只做指标组件时交易回测计数仍为0。文件上传或模型回答结束都不是研究目标completed的条件。

阻断分类至少区分：缺本机交接输入、缺原历史版本、接口暂不可达、缺原外置模块、缺账本/查询功能、平台等价未证明、需要经济规则确认。记录已经尝试的接口、时间和实际响应/异常，DNS失败与“供应商没有该数据”不能混为一类；可独立推进的任务同时列出。

首期优先任务为收尾第64批正式验收、实现Git元数据导出及新电脑阅读验证、核实股本/PCF/名称与退市换股权益、继续剩余来源审查。执行顺序由当前用户指令及依赖决定；新LLM不能从“64批尚未完成”推断用户要求永远先跑回测再处理项目管理。

## 更新与发布

每个验收里程碑更新任务、证据、必要结果和导航，状态页由它们生成；运行中检查点另登记，保留最近已验收点。字段字典按导入版本保存一次，run摘要按run_id保存一次，结果引用去重。新增证据用新记录替代并关联旧记录，避免反复复制整个项目历史。

提交前核对：README/AGENTS入口可达；生成状态与metadata计数相同；所有结论都有证据或明确标为推断/提议；配置、模块和测试确实纳入该提交；历史输入缺失按对象列出；包manifest/receipt对应真实存在的归档，尚未生成的包不能标为可迁移；拟提交清单不含逐日载荷及机器数据库。

提交到本地和推送到远端分别记录。用户让其他LLM读远端时，应引用明确的分支/提交及README入口，避免让模型把尚未同步的本机结论当成远端状态。本轮只是计划，尚未完成上述导出和发布。

## 仅Git阅读验收

在仅含Git文件的独立目录中回答以下问题，每个事实附仓库文件路径或对象ID，回答不得依赖本机repo、数据大表或未上传的聊天上下文。

1. 项目的长期目标是什么，目前哪些阶段完成，哪些仍在执行？
2. 695、213、211、12、14、67分别统计什么，为什么不能互相替代？
3. 哪些策略有已验收交易结果，哪些只是研究组件；原策略完整等价复现数量是多少？
4. BP为何只有短窗口有效，国航/复星为何采用稳定修正版，原实验如何保存？
5. 茅台与三进兵近期表现如何，复星100万元的低回撤如何解释，成本/基准有什么限制？
6. 财务数据如何存储，哪些字段可查询，为什么严格历史财务可用仍为0？
7. 微盘400、小盘价值100、ETF和期货各自缺什么，已有接口尝试证明了什么？
8. 已确认的近似变体有哪些，哪些问题尚待用户回复，什么建议需要新决策？
9. 框架已有能力、分钟研究结果和交易结算缺项是什么，相关代码及验证在哪里？
10. 新电脑缺哪些输入和实验载荷，哪些包实际存在，如何恢复所选实验而保持冻结输入？
11. 下一步哪些任务可执行，完成条件是什么，哪项先做取决于什么依赖？
12. 基于现有证据，最值得做的三项分析/补数/开发是什么，预计新增什么证据，哪些判断仍是假设？

结构和引用完整性由脚本校验，理解质量用独立阅读者验证；可以在用户要求其他LLM评估时完成，不依赖某个特定模型或专有平台。验收以引用正确、状态口径一致、承认缺失和建议可验证为准。缺完整载荷时，LLM可以给出有范围说明的分析建议，不声称重新计算全区间结果。

本轮只写规范，未执行上述仅Git阅读验收，也未请求其他模型评审或运行元数据导出。规范链接与空白已核对；实现及独立阅读验收作为后续计划任务。
