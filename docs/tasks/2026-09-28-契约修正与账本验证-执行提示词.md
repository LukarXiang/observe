## 目标

## A. 组合与账本：改成逐日循环（改 `modules/15`、`16`、`18`，`00` 的模块地图与流程同步改）

**A1. 一个逐日循环协调组合与账本。** 预测分数可以提前算好并冻结；**订单不能提前批量生成**，必须在循环里根据当时的真实持仓和现金生成。
订单、成交、持仓、现金流水都是这个循环模拟产生并保存的结果，不能假设历史上的计划都成交了。每个交易日 t 的固定顺序：

1. **盘前**：处理当天生效的公司行动（见 B 节）；昨天买入的股份变为可卖；到账日为 t 的应收分红转入可用现金；
   上市可卖日为 t 的新增股份变为可卖。
2. **开盘成交事件**：执行 t−1 收盘后生成的订单，先卖后买（资金规则见 A2）。
3. **撤单**：没成交的剩余数量撤销。下一次是否再下单，由 A3 的补单规则决定。
4. **收盘估值与勾稽**：检查净值恒等式，写入当日净值。
5. **决策**（t 收盘数据可用后）：若 t 是调仓日，按冻结的分数和**当前实际持仓与现金**生成新的目标名单和订单；
   若不是调仓日，只按 A3 生成补单。订单在 t+1 开盘执行。

实验管理文档（`18`）里「组合 → 账本」这两个先后阶段合并为一个阶段「组合与账本循环」。它的缓存键包含：预测表指纹、组合配置、账本配置、执行规则集、数据快照。

**A2. 开盘资金规则**（配置项 `open_cash_policy`，两个取值）：

| 取值 | 含义 | 地位 |
| --- | --- | --- |
| `sell_then_buy` | 同一开盘事件内先卖后买，卖出所得（扣除卖出费用）可以立即用于随后的买单 | **默认值**。A 股卖出资金当日可用于买入，这个近似在日频下更接近现实 |
| `preopen_cash_only` | 买单只能用本事件开始前的可用现金，卖出所得要等到下一个交易事件才能用 | 保守对照情景 |

两种都属于「日频开盘参考价近似」：用当日开盘价加方向滑点作为成交价，不模拟集合竞价的真实撮合与排队。文档和报告里都**不得**称为精确撮合。

**A3. 调仓与补单规则。** 默认每 5 个交易日调仓一次。调仓日生成**目标名单**，两次调仓之间目标名单保持不变。非调仓日：

- 目标名单之外、仍持有的股票（上次卖出失败的），每天继续生成卖单，直到卖出或进入下一个调仓日；
- 目标名单之内、尚未持有或持有不足的股票（上次因资金、涨停、停牌没买进的），每天继续生成买单，
  金额取「目标金额与当前可用现金中较小者」；
- 已持有的目标股票**不因价格变动做再平衡**。

配置项 `refill_between_rebalance` 默认为 `true`；设为 `false` 时，调仓之间不补单。这条规则解决的是「卖出回款不能同时刻使用 + 订单当日撤销 + 5 日调仓」叠加后产生的、非策略本意的现金闲置。

**A4. 调仓日的选股优先级**，按下面的顺序执行：

1. **强制退出**：已持有、但当天不在研究候选中的股票（如变成 ST、长期停牌），生成卖出意图。**不受最大换出数限制，也不计入换出数。**
2. **分数缺失的持仓**：保持不动、计入持仓名额，并记录原因 `score_missing`。不当作最差分数强卖。
3. **排名缓冲**：其余持仓中排名在前 N+b 名以内的保留（N 为目标持股数，默认 20；b 为缓冲，默认 10）。
4. **普通换出**：剩余持仓按分数从低到高卖出，数量受最大换出数 `max_sell` 限制：
   - `max_sell = null`：不限；
   - `max_sell = 0`：除强制退出外，不做任何普通换出；
   - 正整数 k：最多换出 k 只。
   「纯 Top-N」的配置写法是 `buffer = 0` 且 `max_sell = null`（原文档「都设为 0 就退化成纯 Top-N」是错的，必须改掉）。
5. **新买入**：先确定「保留集合」（第 2、3 步保留的持仓，以及因数量上限没有换出的持仓），再从未持有的股票中按分数从高到低补足到 N 只。强制退出和普通换出的持仓不计入保留集合。
6. **卖出失败的持仓**（跌停、停牌）仍然占用资产和现金；它们在下一次调仓前不计入目标名单，但买单能用的资金自然会因此减少。

每只目标金额 = 调仓日收盘总净值 / N，受单只上限约束。执行时资金不够，按分数从高到低依次买，排在后面的缩量或放弃，不借钱。

**A5. 订单记录的是意图，股数在执行时才算。** 买单记录「目标金额」，执行时按成交价和买入单位向下取整成股数；
卖单记录「卖出全部」或「卖出比例」，执行时按当时的可卖股数计算。这样一来，决策日到执行日之间遇到除权，股数也不会算错（见 B3）。

**A6. 成本情景。** 「费率加倍」「滑点加倍」等情景，一律用**同一份预测和同一套组合配置，把整个逐日循环重跑一遍**。
「固定订单重放」只保留为一个单独命名的诊断项（`fixed_order_replay`），不能替代成本情景比较。`17` 里「同一份订单分别在不同费率下各跑一遍账本」这句必须改掉。

## B. 公司行动、分红税与估值（改 `modules/10`、`16`，`CONTEXT.md` 补词）

**B1. 四个日期分开存储、分开处理**：股权登记日、除权除息日、现金到账日、新增股份上市可卖日（红股上市日）。
`corp_actions` 表增加字段 `bonus_list_date`。BaoStock 分红表的 `dividStockMarketDate` 即红股上市日。

- 除权除息日：现金分红记为应收分红（到账日, 金额）；送转股按比例增加总股数，但新增部分记为「待上市股份」，**不可卖**；
- 红股上市日：待上市股份转为可卖；
- 到账日：应收分红转为可用现金。

删除 `16` 中「新增股数当天即可卖」的表述。

**B2. 日期缺失时从严处理**，并标 `assumed`、在报告的限制说明里计数：

- 到账日缺失：2014-01-01 以后的事件按除息日处理（实测 600519 在 2014 年以后两者相同）；2014 年以前的事件按除息日后第 10 个交易日处理
  （实测 2013 年及以前晚 4–10 个自然日）。这个 2014 年的分界点必须在阶段 1 用全量数据统计验证，并写进待验证清单；
- 红股上市日缺失：按除权除息日后第 1 个交易日处理，同样列入阶段 1 的验证清单。

**不得**在到账日缺失时提前释放现金而不作说明。

**B3. 除权跨越未执行订单**：订单在 t−1 收盘生成、t 日开盘执行，t 恰好是除权除息日时——

- 买单按 A5 以金额下单，执行时用除权后的开盘价计算股数，不需要额外调整；
- 卖单按 A5 以「全部」或「比例」下单，执行时用除权后的可卖股数（新增的待上市股份不可卖）；
- 涨跌停判断用数据源给出的前收盘价，它在除权日已经是除权参考价。

**B4. 停牌期间遇到公司行动**：停牌持仓的估值价 = 最近有效收盘价按除权公式调整后的参考价：
`(P − 每股现金 + 配股价 × 每股配股比例) / (1 + 每股送转 + 每股配股比例)`，其中 P 为停牌前最后收盘价。能取到数据源给出的除权参考价时，优先用数据源的值。这个估值价与是否参与配股无关；不参与配股只意味着股数不变，由此产生的价值下降如实计入净值。
估值记 `stale_price = true`。复牌日用数据源的前收盘核对，差异列入审计。**不允许出现股数增加、估值价却没调整的情况。**

**B5. 分红税口径**：首版按**税前**现金分红入账，扣除交易费用，但**不扣**个人股息红利所得税（A 股按持股期限适用不同税率，精确计算需要逐笔跟踪持股期）。
报告首页必须写明「收益已扣交易费用，未扣个人股息红利所得税」，不得称为个人税后收益。

## C. 标签与指标（改 `modules/13`、`17`）

**C1. 标签与账户收益的区别。** 现行标签用后复权开盘价计算，相当于假设「现金分红按除息价立即再投资」「配股按复权因子处理」。
账本却是「分红先记应收、到账后成为现金、不自动再投资」「不参与配股」。两者系统性地不同。

- 标签改名为 `adj_open_to_open_h`，说明里写明上述假设，并写明它只作排序目标，不等于账本收益；
- 模块 `17` 的因子层报告要注明「分组收益基于复权标签，不是可实现收益」；
- 增加核对用例：同一只股票在配股、现金分红期间，复权标签收益与账本持有收益的差异方向和数额要能解释。

**C2. 组合指标的精确定义**（替换 `17` 中的现有公式）：

- 期初净值 E₀ = 第一个交易日开盘前的初始资金；日收益 rₜ = Eₜ / Eₜ₋₁ − 1。第一天的交易费用计入 r₁。
- 年化系数 A = 242（配置项）；无风险利率 rf 是年化利率（默认 0），日无风险收益 rf_d = (1 + rf)^(1/A) − 1。
- **夏普比率** = mean(rₜ − rf_d) / std(rₜ − rf_d, ddof = 1) × √A。标准差为 0 或样本少于 20 天时为「不可定义」。
- **主动日收益** aₜ = rₜ − bₜ（bₜ 为基准日收益）；**信息比率** = mean(a) / std(a, ddof = 1) × √A。
- **相对净值** = (Eₜ / E₀) / (Bₜ / B₀)，只作图示，不参与年化计算。
- **年化收益** = (E_T / E₀)^(A / T) − 1，T 为收益天数；**年化收益率差** = 策略年化 − 基准年化。它与「主动收益的年化」是两个不同的指标，分开命名。
- **缺失值**：策略日收益由账本逐日产生，不应缺失；基准缺失的日子不参与主动收益相关指标，报告写明缺失天数，**不删除策略的任何日子**。
- 所有标准差用 ddof = 1。

## E. 快照、任务与复现（改 `modules/10`、`18`、`19`，决策记录第 13 条）

**E1. 按批次发布数据。** 一次数据更新任务产生一个批次清单 `data/batches/<batch_id>.json`，列出本批次涉及的全部表和分区。
日线、复权因子、公司行动必须放在同一个批次里，审计通过后才一次性发布：原子地改写 `data/PUBLISHED.json`（先写临时文件，再改名替换）。
快照复制某个已发布状态。研究读取时只认已发布的批次，永远看不到「日线已更新、复权因子还没更新」的中间状态。
原来每张表单独维护的 `CURRENT.json` 改为由 `PUBLISHED.json` 统一管理。

**E2. 数据清理必须保护以下各项**：当前已发布的批次、所有保留的快照、被任何实验或实验变体引用的快照、正在运行的任务所固定的输入。

**E3. 跨进程互斥。** 命令行、Web 任务、独立下载脚本使用**同一个**操作系统级文件锁：
`data/locks/baostock.lock` 管 BaoStock 会话，`data/locks/data-writer.lock` 管数据写入。拿不到锁就立即失败并提示「谁在占用」。
不再采用「先查没有任务、再启动」这种非原子检查，决策 13 的实现方式要相应改写。锁的实现用 `filelock` 包（进程退出时操作系统自动释放）；第二轮实现时再加这个依赖。
