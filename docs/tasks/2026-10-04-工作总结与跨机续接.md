## 3. 新电脑恢复步骤

### 拉取源码、复制并校验交接包

在新电脑项目目录执行 `git pull --ff-only origin master`；首次克隆使用 `git clone https://github.com/LukarXiang/observe.git`。另把本机以下文件复制到新电脑下载目录或外接磁盘：

```text
data/handoff/observe-2026-10-04-batch2.tar.gz
data/handoff/observe-2026-10-04-batch2.receipt.json
```

包没有上传到 GitHub。压缩大小 **3.30 GiB**（3,548,336,837 字节），解包文件合计约 **4.35 GiB**，另留出依赖和新实验空间。逐文件清单和包凭据在 Git 文档中也有副本。先在仓库根目录核对压缩包 SHA256 和 `receipt.json` 中的 `archive_sha256`；Mac / Linux 可执行 `shasum -a 256 /实际路径/observe-2026-10-04-batch2.tar.gz`。路径含空格时加引号。

新克隆、还没有本地 `data/` 和策略来源目录时，解包到仓库根目录：

```bash
tar -xzf /实际路径/observe-2026-10-04-batch2.tar.gz -C .
```

若已有研究数据或修改过的策略来源，先解包到独立临时目录，核对冲突后迁移，不在已有数据上直接解包覆盖。包不会带入旧机器的实验登记 SQLite；原财务目录也不在包中，你已下载的财务文件保持在 `repo/` 下。

### 重建当前环境

检查 `command -v uv`、`uv --version`，使用根目录锁文件，不安装系统 pip 或 Conda。Mac 开发规范可另复制原机 `/Users/zuozhe/Setups/tool/Mac开发环境与Coding-Agent工具链建设规范_v1.0.md` 到自己的环境文档目录；无需复制全局 shell 或 Agent 配置。

```bash
uv sync --frozen --python 3.12.14 --extra ml --extra data --dev
uv run --frozen --extra ml --extra data python -c "import lightgbm, baostock; print(lightgbm.__version__)"
uv run --frozen --extra ml --extra data python scripts/prepare_handoff.py verify --manifest docs/handoff/observe-2026-10-04-batch2.manifest.json --financial-inputs
```

验证应输出 `status: ok`。原始财务文件尚未放到上述位置时，可以先去掉 `--financial-inputs`，完成标准数据续接；核实来源或重导入前再补齐此校验。

`ml` 用于 LightGBM 四模型研究，`data` 用于 BaoStock 新取数，离线规则策略本身不需要这两个可选包。Mac 如导入 LightGBM 报缺 `libomp.dylib`，先检查 `brew list --formula libomp`；确认缺失后，按环境规范通过 Homebrew 安装 `libomp` 并记录。这里不用升级整套工具或编译器。

Windows / WSL 也使用当前根锁文件，各自创建独立 uv 环境，路径可以不同，不复制 Mac `.venv`。`env/quant/` 是早期环境归档，不要用其旧锁文件覆盖根锁文件。保留外部环境目录时可为该项目单独设置 `UV_PROJECT_ENVIRONMENT`，再执行同一套根项目 `uv sync --frozen`；Linux 包校验可用 `sha256sum`，PowerShell 可用 `Get-FileHash -Algorithm SHA256`。本次真实搬迁验收在同一 Mac 的独立目录完成，其他系统的二进制依赖与浮点差异仍须由复现报告判断。

如需前端，再检查 Node.js 24 LTS 与 npm prefix（Mac 为 `~/.local`），在 `web/` 内执行 `npm ci`、`npm run build`。仅跑后端研究不必安装前端依赖。
