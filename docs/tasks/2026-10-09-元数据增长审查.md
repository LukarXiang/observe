# 元数据增长审查

第78批正式验收后、最终元数据导出前，本机`du -sh data/metadata`显示磁盘占用约228 MiB；catalogs约28 MiB、states约187 MiB、exports约8.7 MiB、progress约124 KiB、financials约3.6 MiB。这是文件系统占用的定向盘点，不是Git对象历史或远端仓库大小，也不是全载荷容量。当前已超出[Git管理计划](2026-10-08-Git追踪与跨机数据管理计划.md)的50 MiB工作树审查目标，不能继续声称满足该目标。

历次状态把相同的运行摘要、能力及证据等再次放入新state，累计增长主要在states；目录版本也随审查累计增长。原导出单文件5 MiB、单批20 MiB门槛仍有工具检查，最近进行中导出为16,282,391字节/258文件，未超单批门槛；单批合格不能证明累计大小合格。更多原始行情、实验载荷和repo仍在Git外。

旧states/exports/catalogs、实验及manifest继续只读保留，不删除、不移动或改写旧对象，也不重写Git历史。最新根index继续提供明确阅读入口，其他LLM不需要遍历所有历史状态。新电脑仍先verify元数据，按index读取本次任务/证据，再迁移所需载荷；目录大小不改变财务/交易准入门禁。

后续新增任务是核对逻辑字节与Git对象增量，给新导出增加按内容SHA共享稳定摘要/证据对象的设计和验证，使新state主要保存版本指针和本批变化。优先复用现有catalog、字典和manifest去重机制；不得修改已经签名的旧state，当前导出阅读/验证接口也须兼容旧版本。必要验证包括仅Git阅读、旧导出继续verify、修改共享对象拒绝、同ID冲突拒绝、完整引用/SHA与最新验收/进行中区分。

本次只记录增长证据与后续计划，未修改导出格式或声称已经完成去重。代码/文档及第78批结果仍待用户自行提交上传；原50 MiB目标需在后续设计中明确新增控制范围和历史保留范围，不能通过静默删档实现。
